## 0. 需求溯源（五问）

1. **谁要的**：项目所有者本人。
2. **解决什么已发生的问题**：现在一封邮件只能贴一个标签。「什么类型」和「要不要我回」「多急」是不同性质的信息，塞不进同一个标签，只能自己点开看。
3. **不做会怎样**：分类只能表达一件事，想同时看类型和是否需要回复，还是得逐封点开自己判断。
4. **怎么算做成**：见第 5 节 R1–R34。每封新邮件一次请求拿到所有已开启组的结果，各组结果以胶囊形式排在邮件时间前面，按组顺序从左到右，时间永远在最后。
5. **为什么不是只改样式**：数据从「一封邮件一个标签」变成「一封邮件每组一条结果」，要写数据搬家、改列表查询、改搜索、改 AI 请求与解析、改设置界面，牵动数据层、AI 层、命令层、界面层。

## 1. 目标与边界

### 1.1 本规格包含

- 把本地标签升级成「标签组 + 标签」两层。标签组就是判断维度。
- 三种组类型：选择题（choice）、是否题（boolean）、打分题（score），分别对应 jev 的三种题型。
- 三个默认组：内容分类（选择题，沿用现有八条标签）、需要我回复（是否题，需要回复 / 无需回复）、紧急程度（打分题，1–5）。
- 组可新建、改名、删除、排序；每组独立开关、独立把握门槛、独立兜底设置。
- 一次 jev 请求同时问所有已开启的组，结果分别落库；单组失败不影响其它组。
- 邮件列表行、会话折叠行、读信页在时间前面按组顺序显示多个胶囊；打分题显示数字胶囊，颜色随数值。
- 右键邮件按组手动修改；手动改过的组锁定，AI 不再覆盖。
- 搜索统一为 `tag:组名:值`，支持打分题 `tag:组名:>=3`；删除 `label:`。
- 老数据搬家：现有标签与已贴标签原样进入「内容分类」组，不丢。
- 版本号提升到 0.4.0。

### 1.2 本规格不包含

- **不做多层细分**：不会先分大类再对某类继续细分。每个组各自独立判断，互不派生。
- **不做多选**：每个组只出一个结果。
- 不做组之间的联动规则（比如「推广且不急就自动归档」）。只判断和显示，不自动处置邮件。
- 不做批量分类；右键仍然只对点中的那一封生效。
- 不把标签或分数同步回邮箱服务器；全部是本地数据。
- 不给 jev 以外的站点开放这些组；分类仍只认 TypeSafe jev。
- 不自动补跑历史邮件；只跑新邮件，老邮件靠右键「立即分类」。
- 不开放任意取色器和十六进制颜色；颜色仍然只从固定色板选。
- 打分题不做自定义档位描述：档位描述由上下限自动生成（见 3.4）。
- 不让模型决定标签颜色、组顺序、显示位置。
- 不做 macOS / Linux 适配；项目当前以 Windows 为发布目标。

## 2. 架构决策（含反选理由）

### Decision D1：标签升级为「组 + 标签」，一封邮件每组一条结果

- **Reason**：用户选了方案一。一套代码管所有组，以后加组不用改表结构。
- **Alternatives Considered**：另开一张表给新组（两套几乎一样的代码，越拖越乱）；所有组结果塞成一坨 JSON 存在邮件上（没法按组建索引，搜索会变慢，数据也不好校验）。

### Decision D2：组就是维度，三种类型对应 jev 三种题型

- **Reason**：jev 官方一次请求支持多个问题，题型正好对上：选择题 → 选一个标签；是否题（noul）→ 返回 0–1 的概率；打分题（score）→ 返回各档位概率。三种维度各用最合适的题型，不硬凑。
- **Alternatives Considered**：全部用选择题（是否题和打分题都能硬凑成选择题，但「需要我回复」拿不到概率，紧急程度也拿不到档位分布）。

### Decision D3：一次请求问完所有开启的组

- **Reason**：省钱、省时；一次外发就把该给的信息给全。
- **Alternatives Considered**：每组发一次请求（请求数翻倍、费用翻倍，中途失败还会留下半套结果）。

### Decision D4：组级独立开关 + 组级门槛

- **Reason**：用户要能只开想跑的组，控制外发范围和费用；每组内容不同，把握要求也该各定各的。
- **Alternatives Considered**：一个总开关管所有组（省事但没得选）。

### Decision D5：手动改过就锁定该组

- **Reason**：人工判断优先级高于模型。只锁被改的那一组，同一封邮件的其它组照常跑。
- **Alternatives Considered**：手动只是临时纠正，下次重跑还是按模型结果覆盖。

### Decision D6：低于门槛的处理按组区分

- **Reason**：有兜底标签的选择题组归兜底（跟现在「其他」的行为一致）；没有兜底的组空着，不显示没把握的结果误导人。
- **是否题组例外**：它本身就是一条分界线（概率 ≥ 门槛显示第一个标签，否则第二个），始终显示一个，不存在空着。
- **Alternatives Considered**：所有组一律空着（内容分类的「其他」就没意义了）；所有组一律显示模型结果（没把握的结果和确定的结果看起来一样，误导）。

### Decision D7：搜索统一 `tag:组名:值`，删除 `label:`

- **Reason**：用户明确要求。组名必写，避免不同组里的同名标签互相干扰。
- **影响**：这是破坏性改动，老的 `label:` 查询失效（会被当普通关键词处理）。规格里明确写出来，不做兼容别名。
- **Alternatives Considered**：保留 `label:` 当别名（用户明确要求删掉）；统一用 `tag:` 但组名可省（两个组有同名标签时分不清）。

### Decision D8：数据仍然只存本机

- **Reason**：沿用原规格 D2 / D8。标签、颜色、分数、门槛、开关都只在本机 SQLite 或 `settings.json`，不参与账号同步。
- **补充**：发出去的只有正文前 2000 字符，以及判断必需的元数据（组名、标签名、打分题上下限）。颜色、门槛、排序、历史结果一律不发。

## 3. 接口与数据

### 3.1 数据模型（新增迁移 `0014_mail_label_groups.sql`）

**新表 `mail_label_group`（标签组）：**

```sql
CREATE TABLE IF NOT EXISTS mail_label_group (
    id                   INTEGER PRIMARY KEY AUTOINCREMENT,
    name                 TEXT NOT NULL,
    kind                 TEXT NOT NULL CHECK (kind IN ('choice', 'boolean', 'score')),
    enabled              INTEGER NOT NULL DEFAULT 0 CHECK (enabled IN (0, 1)),
    confidence_threshold REAL NOT NULL DEFAULT 0.75,
    score_min            INTEGER,
    score_max            INTEGER,
    sort_order           INTEGER NOT NULL DEFAULT 0,
    created_at           TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
    updated_at           TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now'))
) STRICT;

CREATE UNIQUE INDEX IF NOT EXISTS idx_mail_label_group_name ON mail_label_group (name);
```

- `kind`：`choice` 选择题、`boolean` 是否题、`score` 打分题。
- `enabled`：这一组是否参与自动分类。
- `confidence_threshold`：这一组的把握门槛。
- `score_min` / `score_max`：只有打分题组填，其它组为 NULL。

**改造 `mail_label`（标签）：**

- 新增列 `group_id INTEGER NOT NULL REFERENCES mail_label_group(id) ON DELETE CASCADE`。
- 唯一索引从「名字唯一」改成「同一组内名字唯一」：`CREATE UNIQUE INDEX idx_mail_label_group_name ON mail_label (group_id, name)`。
- 兜底标签改成「同一组内最多一个」：`CREATE UNIQUE INDEX idx_mail_label_group_fallback ON mail_label (group_id) WHERE is_fallback = 1`。
- 颜色约束沿用固定色板（gray / red / orange / amber / green / teal / blue / indigo / purple / pink）。

**重建 `message_label`（每封邮件每组一条结果）：**

```sql
CREATE TABLE IF NOT EXISTS message_label (
    message_id  INTEGER NOT NULL REFERENCES message(id) ON DELETE CASCADE,
    group_id    INTEGER NOT NULL REFERENCES mail_label_group(id) ON DELETE CASCADE,
    label_id    INTEGER REFERENCES mail_label(id) ON DELETE CASCADE,
    score_value INTEGER,
    source      TEXT NOT NULL CHECK (source IN ('auto', 'manual')),
    confidence  REAL,
    updated_at  TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
    PRIMARY KEY (message_id, group_id),
    CHECK ((label_id IS NULL) <> (score_value IS NULL))
) STRICT;

CREATE INDEX IF NOT EXISTS idx_message_label_group ON message_label (group_id);
CREATE INDEX IF NOT EXISTS idx_message_label_label ON message_label (label_id);
```

- 选择题组和是否题组写 `label_id`；打分题组写 `score_value`。两者必有一个、只能有一个。
- 主键是（邮件, 组），所以同一封邮件同一组永远只有一条，重跑就是覆盖。

**数据搬家（在同一个迁移里按顺序做）：**

1. 建 `mail_label_group`，先插入「内容分类」（choice）、「需要我回复」（boolean，门槛 0.5）、「紧急程度」（score，1–5），三个组 `enabled = 0`。
2. 给 `mail_label` 加 `group_id`，把现有八条标签（客户、账单、通知、推广、招聘、同事、家人、其他）全部指向「内容分类」，颜色和排序原样保留；「其他」仍然是兜底。
3. 插入「需要我回复」组的两个标签：需要回复（红色）、无需回复（灰色），排序 10 / 20。
4. 重建 `message_label`，把老的（邮件, 标签）记录搬进来，`group_id` 全部填「内容分类」，`label_id` 照旧，`source` 和 `confidence` 照旧，`score_value` 为 NULL。
5. 迁移失败整体回滚，不允许出现「标签在、组没建」这种半套状态。

### 3.2 jev 请求适配（`crates/mail-ai`）

新增一次请求多问题的适配函数（替换现在的单问题 `classify_mail`）：

- 地址不变：`POST {base_url}/systemone`，已带 `/systemone` 时不重复拼。
- 认证不变：`Authorization: Bearer <密钥>`，密钥取自系统保险箱。
- 请求体形状：

```json
{
  "state": "邮件正文前 2000 个字符",
  "model": "jev-latest",
  "questions": {
    "g1": {
      "type": "choice",
      "instructions": "根据内容给这封邮件选一个类别：只能从 criteria 里选一个。",
      "criteria": { "客户": null, "账单": null, "其他": null }
    },
    "g2": {
      "type": "noul",
      "instructions": "这封邮件需要收件人亲自回复吗？"
    },
    "g3": {
      "type": "score",
      "instructions": "这封邮件的紧急程度是多少？",
      "criteria": ["完全不急", "不太急", "一般", "比较急", "非常急"]
    }
  }
}
```

- 问题编号用 `g<组编号>`，编号不会发给模型，只是取结果用的键。
- 选择题的选项放 `criteria`，键是标签名、值是 `null`（官方写法）。
- 是否题用 `noul`，返回 0–1 的概率。
- 打分题的档位描述由上下限自动生成，见 3.4。
- 应答解析：按 `answers.g<编号>` 逐组取；每题自带 `type`，类型与本地组类型对不上就跳过该组。
- 超时 15 秒，与现在一致。
- 站点不支持、模型为空、正文为空、没有任何已开启的组：直接按参数错误返回，不发请求。

### 3.3 编排（`crates/mail-core`）

- `AiFunction::Classify` 保留不变，仍然只认 TypeSafe jev 站点。
- 分类编排改成「一次请求、按组落库」：
  1. 取所有 `enabled = 1` 的组，按 `sort_order` 升序；一个都没有就返回「没有开启任何标签组」。
  2. 校验每组都能出结果：选择题组至少一条标签、是否题组正好两条标签、打分题组上下限合法（2 ≤ 档位数 ≤ 10，且下限小于上限）。
  3. 读正文纯文本，截前 2000 字符；空正文按错误处理。
  4. 组请求体，发一次请求。
  5. 整个请求失败（超时、网络、非 200）：本次一组都不写，记审计，静默返回错误。
  6. 请求成功但某一组的结果不合法：只跳过那一组，其它组照常写。
  7. 落库前逐组判断：该邮件这一组已经是 `manual` → 跳过，不覆盖。
  8. 按组类型和门槛换算结果（见 4.2），写 `message_label`。
- 审计：功能、站点、模型、是否外发、本次各组结果摘要（组名 + 标签名或数字）；**不记正文**。

### 3.4 打分题档位怎么生成

- 组里只存上下限两个整数，档位描述由代码生成，不存库。
- 档位数 = 上限 − 下限 + 1，必须在 2–10 之间（jev 打分题最多 10 档）。
- 中文档位描述按档位比例生成，例如 1–5 生成：完全不急 / 不太急 / 一般 / 比较急 / 非常急；1–10 生成从「最不急」到「最急」的十档描述。
- 固定描述表按档位数分档（2 档、3 档、4 档、5 档、6–10 档各一套），保证同一组的档位描述稳定，不随版本漂移。
- jev 返回各档概率后，**取概率最高的那一档**，换算成数字：下限 + 档位下标。例如 5 档里最高概率是第 3 档（下标 2），显示 3。
- 把握程度用该题返回的 `confidence`。

**新增命令：**

- `preview_classify_messages` 增加「本次将开启哪些组」的说明，其余不变（站点、模型、域名、是否本地、目标邮件与内容哈希、一次性令牌）。
- `classify_messages` 语义不变：拿令牌、对指定邮件跑一次多组分类。
- `list_mail_labels` 删除，由 `list_label_groups` 取代。

**列表数据结构：**

`InboxMessage` 去掉 `labelId` / `labelName` / `labelColor` 三个字段，改成：

```
groupResults: [
  { groupId, groupName, kind, labelId, labelName, labelColor, scoreValue }
]
```

- 按组的 `sort_order` 升序排列。
- 没结果的组不出现在数组里。
- 会话折叠行取最新一封邮件的 `groupResults`。

### 3.6 开关、门槛与排序存哪

- 总开关 `classify_enabled`、手动分类免确认开关 `classify_skip_manual_confirm` 继续存本机 `settings.json`，不进 `setting` 表、不参与设置同步。
- 每组的开关、门槛、上下限、排序存在 `mail_label_group` 表里，同样是本机数据。
- 老的全局门槛 `classify_confidence_percent` 保留字段（避免老配置报错），但迁移时读一次写进「内容分类」组的门槛；此后不再使用，新建组的默认门槛固定 0.75。
- 界面改完立刻落盘，并同步更新外壳里的共享状态。---

## 4. 行为

### 4.1 设置页行为（AI 功能内）

- 原来「分类标签管理」区升级成「标签组管理」，入口位置不变（仍在 AI 功能里）。
- 组列表按排序显示，每组一行，显示：组名、类型、开关、把握门槛、组内标签与颜色。
- 组操作：新建、改名、删除、上移下移（或拖动排序）。
- 新建组时选类型：
  - 选择题：填组名，加标签（名字 + 固定色板颜色），可指定一个兜底标签，也可关掉兜底。
  - 是否题：填组名，固定两条标签（默认「需要回复」「无需回复」），可改名、改色；概率 ≥ 门槛显示第一条，否则第二条。
  - 打分题：填组名、下限、上限；档位数必须是 2–10；不配标签。
- 每组一个开关、一个把握门槛输入（默认 0.75，是否题默认 0.5，范围 0.50–0.99）。
- 兜底标签不能删除、不能改色（固定灰色），可以改名；同一组内最多一个兜底。
- 组名和标签名都不许为空、不许重名（组名全局唯一，标签名组内唯一），最长 64 字。
- 总开关「邮件自动分类」保留；总开关关闭时，组开关即使打开也不外发，界面要说明这一点。
- 保留「下次不要提醒」免确认开关，控制手动分类是否逐次弹确认。

### 4.2 自动分类流程

总开关打开后，每轮新邮件扫描中，对每封新落地邮件按以下顺序处理：

1. 总开关没开 → 跳过。
2. 取所有开启的组，按排序升序；一个都没有 → 跳过。
3. 检查该邮件是否已经有组结果：有结果的组里，`manual` 的锁定跳过，`auto` 的本次重算覆盖。
4. 读正文纯文本，截前 2000 字符；空正文跳过并记审计。
5. 组一次请求，把全部开启组的问题一起发出去。
6. 整个请求失败 → 本次一组都不写，记审计，不影响收信，不弹窗。
7. 请求成功 → 逐组解析，单组不合法只跳过该组。
8. 逐组按门槛换算并写库：
   - **选择题**：把握 ≥ 门槛 → 落模型选中的标签；把握 < 门槛且有兜底 → 落兜底；把握 < 门槛且没兜底 → 该组不写。
   - **是否题**：概率 ≥ 门槛 → 落第一条标签；否则落第二条标签；始终写一条。
   - **打分题**：把握 ≥ 门槛 → 落「概率最高档位」换算出的整数；把握 < 门槛 → 该组不写。
9. 写审计：组名 + 结果摘要，不写正文。

补充规则：

- 自动流程只跑新邮件，不自动补跑历史邮件。
- 同一封邮件同一组永远只有一条结果，重跑就是覆盖（`manual` 除外）。
- 超时、网络失败、返回结果不合法都不写半套数据。

### 4.3 右键手动修改（收件箱邮件菜单）

- 右键菜单按组列出，每组展开后显示可选值：
  - 选择题组：该组所有标签 + 「清除本组结果」。
  - 是否题组：两条标签 + 「清除本组结果」。
  - 打分题组：下限到上限的每个数字 + 「清除本组结果」。
- 点某个值：写入该组结果，来源记 `manual`，该组从此锁定。
- 点「清除本组结果」：删掉该组结果并解锁，后续「立即分类」可以重判。
- 菜单保留「立即分类」：只对点中的那一封生效，执行前弹一次外发确认（站点、完整域名、模型、是否本地、目标邮件）；取消则不外发、不写结果。
- 「立即分类」只重判没锁定的组；锁定的组保持不动。

### 4.4 显示

- 邮件列表行、搜索结果行、会话折叠行、读信页，胶囊统一排在邮件时间前面。
- 顺序：按组的排序升序从左到右，时间永远在最后。
- 没结果的组不显示占位；三个组都有结果时就是三个胶囊并排。
- 选择题/是否题胶囊：文字是标签名，颜色是标签颜色，外形沿用现在的彩色胶囊。
- 打分题胶囊：里面只有数字，颜色按数值在区间里的相对位置分 5 档（第 1 档灰、第 2 档蓝、第 3 档黄、第 4 档橙、第 5 档红）；上下限正好是 1–5 时，1 灰、2 蓝、3 黄、4 橙、5 红一一对应。
- 点列表里的胶囊：执行对应的 `tag:组名:值` 搜索。
- 点读信页的胶囊：打开该组的手动修改入口，改完列表立刻刷新。
- 深浅两种主题下都要清楚可读。

### 4.5 搜索

- 统一前缀 `tag:`，格式 `tag:组名:值`，组名必写。
- 选择题/是否题：`tag:内容分类:账单`、`tag:需要我回复:需要回复`；标签名按名称精确匹配，英文忽略大小写。
- 打分题：`tag:紧急程度:3` 是正好等于 3；`tag:紧急程度:>=3`、`tag:紧急程度:<=2` 是比较。
- 可与 `from:` / `has:` / `is:` / `before:` 叠加。
- 组名不存在、值不合法（比如打分题传了文字）→ 给中文提示，不静默返回空结果。
- 组名里不允许出现英文冒号 `:`，避免解析歧义；建组时校验。
- `label:` 不再识别，会被当普通关键词处理；界面提示里不再出现这个写法。

## 6. 安全与隐私

- 密钥只进系统保险箱；数据库、日志、报错信息里都不出现明文。
- 正文只发前 2000 个字符；只发正文纯文本，不发附件、不加载远程图片。
- 发出去的还有判断必需的元数据：组名、标签名、打分题档位描述。颜色、门槛、排序、历史结果一律不发。
- 模型的返回只当数据用，**不触发发送、跳转、删邮件、改文件夹等任何动作**；这些功能唯一的写动作是写本机结果表。
- 默认关闭；总开关关闭立即停止所有组的外发。
- 右键「立即分类」和手动修改每次都先弹确认（开了免确认开关除外）；取消时不读正文、不写结果。
- 审计只记时间、功能、站点、模型、是否外发、各组结果摘要，不记正文。
- 标签、颜色、分数、门槛都是本地数据，不参与账号同步、不上传。
- 邮件正文继续当不可信内容，不能由它触发任何外发、跳转、写库或命令。
