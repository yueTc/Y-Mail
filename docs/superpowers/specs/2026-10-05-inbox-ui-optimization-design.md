## 0. 需求溯源

1. **谁要的**：项目所有者本人。
2. **解决什么问题**：当前主界面只有三栏，默认窗口下中间邮件列表被挤得很窄、很矮；添加邮箱会离开当前收件箱上下文；窗口默认尺寸偏小，四块信息无法同时舒服显示。
3. **不做什么会怎样**：用户仍会在邮箱、邮件列表和正文之间反复挤压滚动；添加账号时上下文丢失；以后一缩放窗口就可能看不到正文。
4. **怎么算做成**：最左侧只有“收件箱、设置”两个图标；选收件箱时看到邮箱栏、邮件列表和邮件内容三栏；选设置时右侧三栏整体切换成一栏设置页；邮箱栏、邮件列表和邮件内容都能用鼠标或键盘调整宽窄；添加邮箱在弹窗内完成；默认窗口足够大且小屏幕能自动收缩。
5. **为什么不是只改样式**：仅调整现有三栏宽度，无法解决“添加邮箱要跳页”“阅读区会被隐藏”“搜索、已读、草稿没有闭环”这些交互缺口。

---

## 1. 目标与边界

### 1.1 本规格包含

- 应用外壳从顶部标签页改为“固定设置栏 + 主工作区”。
- 最左设置栏只保留“收件箱”和“设置”两个图标。
- 收件箱模式改成四栏：设置栏、邮箱栏、邮件列表、邮件内容。
- 设置模式把右侧三栏整体替换成一栏设置页。
- 设置栏固定宽度，收件箱模式下的其余三栏支持拖动调宽、键盘调宽、双击复位和宽度记忆。
- “添加邮箱”改成弹窗，并复用同一套表单入口。
- 默认窗口调整为 `1440 × 900`，小屏自动收缩，最小尺寸保持 `960 × 600`。
- 修正此前审核发现的搜索分页、已读状态、写信草稿保护、同步状态可见性。
- 补齐基本键盘操作、焦点管理、错误提示和完整深色模式。

### 1.2 本规格不包含

- 不改 IMAP、SMTP、OAuth2 的协议行为，只做界面接入和状态呈现。
- 不改正文安全清洗、远程图片默认拦截、人工智能默认关闭和逐次授权规则。
- 不改 MCP 只读、本地标准输入输出、默认关闭和审计规则。
- 不引入新的账号体系、云同步或遥测。
- 不重做品牌视觉，不更换现有 React、Tauri 和本地数据库技术路线。

## 2. 总体布局

### 2.1 收件箱模式

```text
┌──────────┬────────────┬──────────────┬────────────────────────────┐
│ 设置栏    │ 邮箱栏      │ 邮件列表      │ 邮件内容                    │
│ 固定      │ 可拖动      │ 可拖动        │ 可拖动                      │
│ 60px     │ 180–320px  │ 300–560px    │ 最小 360px                 │
└──────────┴────────────┴──────────────┴────────────────────────────┘
           ▲             ▲
           │             │
      拖动条 1       拖动条 2
```

- 设置栏始终固定在最左侧，不参与拖动。
- 设置栏只有“收件箱”和“设置”两个入口图标。
- 邮箱栏和邮件列表之间有一条拖动条。
- 邮件列表和邮件内容之间有一条拖动条。
- 拖动后总宽度不变，只调整相邻两栏的宽度。
- 任何一栏都不能被拖到 0 像素或覆盖别栏。

### 2.2 设置模式

```text
┌──────────┬─────────────────────────────────────────────────────┐
│ 设置栏    │ 设置页（单栏，整块占满右侧区域）                       │
│ 固定      │ 账号与同步 / 代理 / 阅读 / 人工智能 / 外部接入 / 状态     │
└──────────┴─────────────────────────────────────────────────────┘
```

- 点击最左“设置”图标后，右侧的邮箱栏、邮件列表、邮件内容三栏整体消失，替换为一栏设置页。
- 设置页不再显示邮箱栏、邮件列表或邮件内容。
- 设置页内部按分组纵向排列，建议顺序为账号与同步、代理、阅读设置、人工智能、外部接入、数据库状态。
- 点击最左“收件箱”图标后，恢复原来的三栏布局、选中账号、文件夹、邮件和面板宽度。

## 3. 功能需求

### R1 应用外壳与设置栏

> 2026-10-06 追加：设置栏在“收件箱”和“设置”之间新增第三个入口“通讯录”。本节下面写“只允许两个入口”的地方，一律按三个入口理解（收件箱、通讯录、设置），详见 `2026-10-06-contacts-workspace-design.md`。

系统 MUST 把现有顶部“收件箱 / 账号与代理”标签页改为左侧固定设置栏。

- 设置栏宽度固定为 56–64 像素，建议 60 像素。
- 设置栏高度撑满窗口，滚动内容和主工作区互不影响。
- 设置栏只允许两个入口：
  - 收件箱：默认入口，显示邮箱栏、邮件列表、邮件内容三栏。
  - 设置：把右侧三栏整体切换为一栏设置页。
- 当前入口 MUST 有明确选中态。
- 鼠标悬停 MUST 显示中文名称；窄栏下不能只靠图标猜。
- 点击“设置”时，邮箱栏、邮件列表和邮件内容 MUST 全部隐藏，只显示设置页。
- 设置页 MUST 是单栏页面，可以纵向滚动，不出现第二列主导航。
- 设置页内部 SHOULD 分组显示：账号与同步、代理、阅读设置、人工智能、外部接入、数据库状态。
- 从设置页返回收件箱时 MUST 保留上次选中的账号、文件夹、邮件和面板宽度。

**Scenario 1.1**：Given 用户正在看某封邮件；When 点击最左“设置”，再点击“收件箱”；Then 回到原来的邮件和面板宽度，不重新选择账号或文件夹。

**Scenario 1.2**：Given 用户在收件箱模式；When 点击最左“设置”；Then 邮箱栏、邮件列表和邮件内容整体替换为一栏设置页，设置栏仍固定在左侧。

### R2 邮箱栏

邮箱栏 MUST 同时承担账号选择、文件夹浏览和添加入口。

- 顶部显示账号切换器。
- 账号列表按用户顺序显示，并显示账号名称、邮箱地址、颜色标记、未读数。
- 选中账号后显示该账号的文件夹树，包括收件箱、未读邮件、草稿箱、已发送、垃圾邮件、已删除等。
- 每个文件夹显示未读数。
- “添加邮箱”放在邮箱栏底部或账号切换器附近，点击后打开弹窗。
- 添加邮箱 MUST NOT 跳转到整页设置，MUST NOT 丢失当前收件箱上下文。
- 账号同步失败时，在对应账号行显示状态，不影响其他账号。
- 邮箱栏可拖动，宽度限制为 180–320 像素，默认 240 像素。

**Scenario 2.1**：Given 已有两个账号；When 点“添加邮箱”并完成添加；Then 弹窗关闭，邮箱栏刷新，新账号被选中，邮件列表加载新账号收件箱。

### R3 邮件列表

邮件列表 MUST 是主任务区，宽度和高度优先得到保证。

- 顶部工具栏只保留一行主操作：搜索、筛选、刷新、同步状态。
- 搜索语法提示和复杂筛选收进下拉面板，不常驻占高。
- 邮件行显示发件人、主题、摘要、时间、账号色标、附件和星标状态。
- 未读邮件使用更明显的字重或颜色，不能只靠一个很小的红点。
- 点击邮件行打开正文，并进入已读流程。
- 列表支持键盘上下移动和回车打开。
- 邮件列表可拖动，宽度限制为 300–560 像素，默认 420 像素。
- 邮件数量超过可视范围时 MUST 使用虚拟列表，不一次渲染全部行。

**Scenario 3.1**：Given 收件箱有 5000 封邮件；When 用户滚动邮件列表；Then 仅渲染可视区域附近的行，滚动保持流畅。

### R4 邮件内容

邮件内容栏 MUST 作为独立阅读区，不再在小窗口下直接隐藏。

- 未选中邮件时显示空状态和操作提示。
- 选中邮件时显示主题、发件人、收件人、时间、账号、正文、附件和回复转发操作。
- 邮件内容栏最小宽度为 360 像素。
- 正文仍 MUST 在无脚本沙箱中显示，远程图片仍默认拦截。
- 窗口变窄时，三栏按最小宽度压缩，不隐藏内容栏。
- 如果可用宽度不足以容纳所有最小宽度，应用 MUST 保持窗口最小宽度限制，MUST NOT 让阅读区消失。
- 写信打开时，内容栏切换为写信工作区；关闭写信后回到被替换的阅读内容。

**Scenario 4.1**：Given 窗口缩到 `960 × 600`；When 用户点击一封邮件；Then 正文仍能显示，正文区宽度不小于 360 像素，不出现空白不可用状态。

### R5 拖动与宽度记忆

系统 MUST 支持鼠标和键盘调整邮箱栏、邮件列表、邮件内容栏的宽度。

- 拖动条 1 调整邮箱栏和邮件列表宽度。
- 拖动条 2 调整邮件列表和邮件内容栏宽度。
- 拖动过程中 MUST 显示拖动状态，鼠标样式变为左右调整样式。
- 拖动条可见宽度可为 1 像素，可点击宽度 MUST 不小于 8 像素。
- 键盘焦点落在拖动条时，左右方向键每次调整 16 像素，按住 Shift 时每次调整 48 像素。
- 双击拖动条恢复该边界的默认宽度。
- 宽度保存在本机，键名建议为 `em-master.pane-widths.v1`。
- 启动或窗口变化时 MUST 重新校验宽度范围，避免超出窗口。
- 设置栏不参与保存和拖动。

**Scenario 5.1**：Given 用户把邮件列表拖到 500 像素并关闭应用；When 再次打开；Then 邮件列表恢复为 500 像素附近，且总布局不越界。

**Scenario 5.2**：Given 窗口为 `960 × 600`；When 用户拖动分隔条；Then 三栏不小于各自最小宽度，不重叠，不出现横向滚动条。

### R6 添加邮箱弹窗

“添加邮箱”MUST 使用弹窗完成，不离开当前收件箱。

- 触发入口包括邮箱栏“添加邮箱”和设置页里的“账号与同步”。
- 弹窗建议宽度 `min(760px, 90vw)`，高度不超过可用窗口的 90%。
- 弹窗步骤：
  1. 选择邮箱类型：工作邮箱、个人邮箱、QQ、Outlook、Gmail。
  2. 填邮箱地址与认证方式。
  3. 填授权码、密码或拉起 OAuth2 授权。
  4. 展开或收起高级设置。
  5. 测试连接。
  6. 自检通过后保存。
- 高级设置默认收起，包含服务器地址、端口、加密方式、OAuth2 客户端编号、代理选择。
- 常见服务商 MUST 预填推荐服务器和端口，用户仍可改。
- 识别到微软个人邮箱域名（`outlook.com`、`hotmail.com`、`live.com`、`msn.com`）后，新建账号 MUST 自动把认证方式切到 OAuth2、服务商切到微软，并预填 `outlook.office365.com` / `smtp.office365.com`；识别到谷歌 Gmail 域名（`gmail.com`）后，新建账号 MUST 自动把认证方式切到 OAuth2、服务商切到谷歌，并预填 `imap.gmail.com` / `smtp.gmail.com`；用户手动改过认证方式或服务商后 MUST NOT 再自动覆盖。
- 测试连接 MUST 完成 IMAP 登录、文件夹读取和 SMTP 探测，MUST NOT 发送邮件。
- 测试失败时 MUST 区分认证失败、网络不可达、加密失败和代理失败，并给出可读中文提示。
- 测试失败 MUST NOT 写入半成品账号。
- 从邮箱栏打开弹窗时，保存成功后 MUST 关闭弹窗、刷新邮箱栏和账号列表，并选中新账号。
- 从设置页打开弹窗时，保存成功后 MUST 关闭弹窗、刷新设置页账号列表，并显示“进入收件箱”入口。
- 弹窗关闭前若已修改内容，MUST 提示是否放弃。
- `Esc` 可关闭无修改弹窗；有修改时先确认。
- 弹窗打开后焦点进入第一个输入项，并按 Tab 在弹窗内循环。
- 密码、授权码、令牌和客户端密钥 MUST 只进系统保险箱，MUST NOT 出现在数据库、日志、错误提示或界面回显中。
- OAuth2 授权仍走系统默认浏览器和本机回调，弹窗只显示等待状态、取消操作和失败原因。

**Scenario 6.1**：Given 用户填写 QQ 邮箱和授权码；When 测试连接成功并保存；Then 弹窗关闭，新账号出现在邮箱栏，未读数和文件夹开始同步。

**Scenario 6.2**：Given 用户填错授权码；When 测试连接；Then 弹窗显示“认证失败”及修改建议，不保存账号，不泄露授权码。

**Scenario 6.3**：Given 用户已在账号表单里填写内容但尚未保存；When 点击关闭或按 Esc；Then 系统先询问是否放弃本次填写。

**Scenario 6.4**：Given 用户新建账号并填写 `me@outlook.com`；When 焦点离开邮箱框或按回车；Then 认证方式自动变为 OAuth2、服务商自动选微软；用户手动改回授权码登录后，再改邮箱不会被自动覆盖。

**Scenario 6.5**：Given 用户新建账号并填写 `me@gmail.com`；When 焦点离开邮箱框或按回车；Then 认证方式自动变为 OAuth2、服务商自动选谷歌，收件服务器预填 `imap.gmail.com`，发件服务器预填 `smtp.gmail.com`；用户手动改回授权码登录后，再改邮箱不会被自动覆盖。

### R7 默认窗口与启动

系统 SHOULD 把默认窗口调整为 `1440 × 900`。`1440 × 900` 只是默认尺寸，窗口 MUST 保持可自由放大、缩小，不设最大尺寸，最小窗口保持 `960 × 600`。

- 首次启动默认居中。
- 窗口 MUST 保持 `resizable = true`；用户拖动边框可随意放大缩小，上限不设限，下限为 `960 × 600`。
- 放大窗口时，多出来的空间 MUST 优先分给邮件列表和邮件内容；缩小时按 R4、R5 的最小宽度压缩，MUST NOT 隐藏阅读区。
- 若当前屏幕可用区域小于 `1440 × 900`，启动时按屏幕可用区域自动缩小。
- 自动缩小后 MUST 尽量满足最小窗口限制。
- 如果实际屏幕小于 `960 × 600`，作为异常小屏兜底，邮件内容区允许以可关闭的覆盖层显示，MUST NOT 直接丢弃阅读功能。
- 收件箱模式默认窗口必须能同时显示四栏，且邮件列表可视高度不少于 420 像素。
- 不因默认窗口变大而改变邮件数据加载数量。

**Scenario 7.1**：Given 屏幕可用区域为 `1920 × 1080`；When 首次启动；Then 窗口约为 `1440 × 900` 并居中。

**Scenario 7.2**：Given 屏幕可用区域只有 `1280 × 720`；When 启动；Then 窗口自动收缩到可用区域以内，不超出屏幕。

**Scenario 7.3**：Given 用户正在使用默认尺寸窗口；When 拖动窗口边框放大或缩小；Then 四栏实时跟随分配空间，正文和邮件列表不丢失，缩到最小时不出现横向滚动条。

### R8 搜索与筛选

搜索 MUST 保持本地优先，联网补历史必须由用户明确触发。

- 默认搜索只查本地。
- 搜索框回车执行本地搜索。
- 当本地结果已显示但可能还有历史未同步时，显示“继续联网补历史”按钮。
- 联网补历史期间显示进度和可取消状态。
- 结果数量 MUST 区分“共找到 N 封”和“当前已显示 M 封”。
- 当前只显示一页时 MUST 提供“继续加载”，MUST NOT 用总数伪装成全部已展示。
- 简单筛选（全部、未读、有附件、已星标）保留在工具栏。
- 搜索语法提示、日期范围、发件人范围收进可展开面板。
- `Ctrl + K` 聚焦搜索框；`Esc` 退出搜索并回到普通邮件列表。
- 清空搜索框后也 MUST 能回到普通列表。

**Scenario 8.1**：Given 本地有 10000 封邮件；When 搜索关键词；Then 先返回本地结果，成功或失败都不自动联网。

**Scenario 8.2**：Given 本地只找到 120 条而总数是 500；When 结果列表加载第一页；Then 显示“共 500 封，当前已显示 120 封”，并提供继续加载。

### R9 已读与未读状态

打开邮件 MUST 形成完整已读闭环。

- 用户点击邮件行后，先立即将本封标为已读，更新列表样式和未读数。
- 本地已读状态发生失败时，MUST 回滚并提示原因。
- 成功后按现有同步能力回写服务器 `Seen` 状态。
- 账号未读数、文件夹未读数和统一收件箱未读数 MUST 同步刷新。
- 已读邮件再次打开不重复产生同步请求。
- 未读筛选开启时，邮件变已读后应从当前筛选列表移出，并显示短暂提示。

**Scenario 9.1**：Given 未读邮件数为 5；When 打开一封未读邮件；Then 邮件变为已读，未读数变为 4，列表和服务器的本地视图保持一致。

### R10 写信与草稿保护

写信 MUST 使用内容区的独立工作区，不能挤在普通阅读栏宽度里硬塞。

- 写信工作区最小宽度 480 像素。
- 新建、回复、转发都进入同一写信工作区。
- 用户停止输入约 1 秒后自动保存本地草稿。
- 关闭、切换账号、切换文件夹或退出应用前，若存在未保存变化，MUST 提示“保存草稿 / 放弃 / 取消关闭”。
- 发送失败后 MUST 保留草稿和发件箱记录，MUST NOT 静默清空。
- 发送中禁用关闭，避免半途卸载。
- 附件、签名、抄送、密送、联系人补全沿用现有能力。
- 人工智能润色和起草仍 MUST 逐次授权，邮件正文仍按不可信内容处理。

**Scenario 10.1**：Given 用户写了正文但未发送；When 点击关闭；Then 系统提示保存草稿、放弃或取消关闭，选择取消后内容仍在。

**Scenario 10.2**：Given 发送失败；When 用户重新打开该草稿；Then 正文和附件仍在，重试不会重复发送。

### R11 同步状态与反馈

系统 MUST 让同步状态常驻可见。

- 设置页的“账号与同步”分组显示全局同步状态，颜色区分空闲、同步中、失败、暂停。
- 收件箱模式的设置栏不额外增加状态图标，避免破坏“只有收件箱和设置两个图标”的约束。
- 邮件列表工具栏显示当前账号的同步状态徽标。
- 鼠标悬停或聚焦时说明正在同步的账号、文件夹、进度和最近错误。
- 同步失败 MUST 提供重试入口，MUST NOT 只显示一行错误文字。
- 错误提示使用统一组件，重要错误带 `role="alert"` 或等价实时提示。

**Scenario 11.1**：Given 某个账号同步失败；When 用户看邮件列表；Then 当前账号显示失败徽标和“重试”按钮，其他账号仍可使用。

### R12 键盘、焦点与无障碍

- 邮件列表支持方向键移动、回车打开、空格选中。
- 拖动条使用 `role="separator"`，带当前值、最小值和最大值，可用方向键调整。
- `Ctrl + K` 聚焦搜索，`Esc` 优先关弹窗或退出搜索。
- 弹窗打开后焦点锁定在弹窗内，关闭后回到触发按钮。
- 所有仅图标的按钮 MUST 有中文可读名称。
- 所有交互控件 MUST 有可见焦点样式。
- 颜色对比度必须满足普通正文和关键操作可读。
- 错误、成功和同步状态变更使用实时提示。

### R13 深色模式

深色模式 MUST 覆盖所有工作区、弹窗和状态组件。

- 邮件正文阅读主题可以单独设置，但外层界面必须统一跟随深色模式。
- 弹窗、输入框、拖动条、筛选器、附件区、错误提示和空状态都必须有深色样式。
- 不能只改背景和文字，border、阴影、hover、focus、disabled 状态也必须适配。
- 系统主题变化时应即时切换，不要求重启。

### R14 样式令牌与组件纪律

界面优化 MUST 先抽取统一令牌，避免继续写死颜色和间距。

- 颜色令牌：背景、面板、边框、正文、次要文字、强调色、成功、警告、危险。
- 尺寸令牌：圆角、间距、输入高度、按钮高度、拖动条宽度。
- 字体令牌：标题、正文、辅助文字、未读强调。
- 状态令牌：hover、focus、active、disabled、loading、error。
- 组件状态统一：按钮、输入框、标签、弹窗、空状态、错误条、骨架屏。

## 4. 数据与状态口径

- 面板宽度存储在本地，不写数据库，不同步服务器。
- 当前账号、文件夹、选中邮件保持现有业务含义，不因拖动丢失。
- 搜索统计必须来自后端总数，展示数必须来自当前已加载结果数，二者不能混为一项。
- 已读操作先做本地乐观更新，再调用现有同步能力；失败必须回滚。
- 草稿自动保存和发送失败保留草稿使用现有发件箱数据，不新增明文凭据。
- 添加邮箱弹窗只调用现有自检和保存流程，不复制第二套账号逻辑。

## 5. 验收标准

### 5.1 窗口与布局

| 场景 | 要求 |
|---|---|
| `1440 × 900`（收件箱模式） | 四栏全部可见；设置栏固定；邮件列表可视高度不少于 420 像素 |
| `1280 × 800`（收件箱模式） | 四栏全部可见；邮件内容栏不少于 360 像素 |
| `960 × 600`（收件箱模式） | 四栏全部可见；不隐藏阅读区；不出现横向滚动条 |
| 任意尺寸（窗口自由缩放） | 可自由放大缩小且不设最大尺寸；缩到 `960 × 600` 时四栏仍可见，正文不隐藏 |
| 任意窗口尺寸（设置模式） | 点击“设置”后右侧三栏整体切换为一栏设置页；设置栏仍固定；设置页可纵向滚动 |

### 5.2 拖动

- 两条拖动条都能用鼠标拖动。
- 拖动时相邻栏宽变化，其他布局不跳位。
- 最小宽度和最大宽度生效。
- 刷新或重启后宽度恢复。
- 双击恢复默认。
- 键盘左右键可调整，焦点样式清楚。

### 5.3 弹窗

- 邮箱栏“添加邮箱”和设置页“账号与同步”都能打开同一个添加邮箱弹窗。
- 测试连接成功后再保存。
- 认证失败、网络失败、加密失败、代理失败都有可读提示。
- 关闭未保存弹窗有确认。
- 从邮箱栏打开时，保存成功后选中新账号；从设置页打开时，保存成功后显示“进入收件箱”。
- 数据库中查不到任何明文密码、授权码或令牌。

### 5.4 交互闭环

- 搜索默认不联网，继续补历史必须点击。
- 搜索结果区分总数和已显示数，并可继续加载。
- 打开未读邮件后，邮件样式和所有未读计数同步更新。
- 写信关闭有保存草稿、放弃和取消三个选择。
- 发送失败后草稿和附件仍存在。
- 同步状态在设置页“账号与同步”分组和邮件列表工具栏可见。

### 5.5 无障碍与深色模式

- 键盘可完成：聚焦搜索、切换邮件、打开邮件、调整拖动条、关闭弹窗。
- 弹窗焦点不逃出，关闭后回到触发按钮。
- 错误提示可被读屏感知。
- 深色模式下没有明显亮色残留和看不清的控件。

### 5.6 工程验证

每批实现完成后 MUST 跑：

- `cargo fmt --all --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- `npm run build`
- `npm test`

日志和截图放入当天 `.ai-memory` 目录，并更新 `handoff.md`、`project_memory.md` 和当天 `daily.md`。
