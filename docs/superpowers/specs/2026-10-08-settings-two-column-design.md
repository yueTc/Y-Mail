## 0. 需求溯源

1. **谁要的**：项目所有者本人。
2. **解决什么问题**：现在设置页是一整列从上滚到底，九个分组挤在一起，想找某一项要一直往下滚；分组以后还会加，会越滚越长。
3. **不做什么会怎样**：分组继续增加后单栏越来越长，用户找不到要改的东西。
4. **怎么算做成**：见第 5 节验收标准（R1–R10）。
5. **为什么不是只改样式**：新增的「默认拦截远程图片」要动后端读信判定和设置落盘，不只是排版。

---

## 1. 目标与边界

### 1.1 本规格包含

- 设置页由单栏改为两栏：左边一列分类，右边一列显示当前分类的具体内容。
- 左边分类栏的宽度能用鼠标拖动调整，也能用键盘调，双击复位；宽度记住，下次打开还是这个宽度。
- 分类重排与改名，最终共八个分类，顺序为：
  1. 通用（由原「启动」+ 原「阅读设置」合并，放到最上面）
  2. 外观
  3. 账号与同步
  4. 代理
  5. AI功能（原「人工智能」）
  6. MCP（原「外部接入」）
  7. 存储与通知（原「存储目录与通知」）
  8. 通讯录
- 「通用」里新增一个开关：「默认拦截远程图片」，默认开（拦）。
- 右边内容继续复用现有面板组件，不重写业务逻辑。

### 1.2 本规格不包含

- 不改保存逻辑、连接自检、目录迁移、同步、代理的后端行为（只有「默认拦截」这一项是新增）。
- 不做手机 / 平板适配；窗口最小尺寸沿用现状。
- 不做左栏图标；第一版只有文字。
- 不做顶部分类搜索框；八个分类还用不上。
- 不做分类栏折叠 / 收起成图标条；窄窗口只做自动收窄。
- 不动最左那根图标导航栏（收件箱 / 设置 / 通讯录）。

## 2. 架构决策（含反选理由）

### Decision D1：设置页改成两栏，取代旧规格的「必须单栏」

- **Reason**：分组会越来越多，左栏分类能让用户一眼看到全部，不用滚到底找。
- **Alternatives Considered**：保持单栏，只加锚点跳转。
- **Rejected Because**：锚点跳转还是要滚，找起来更绕。
- **Trade-offs Accepted**：推翻 2026-10-05 规格第 2.2 节「单栏、不出现第二列主导航」这条硬要求，需要在旧规格里补一句「已被本规格取代」，免得两份规格打架。

### Decision D2：右边只显示当前分类，切换时「藏起来」不「拆掉」

- **Reason**：某个分类填了一半没保存，切走再切回来内容还在；也不会每次切都重新联网拉一遍数据。
- **Alternatives Considered**：切换时卸载再重新挂载。
- **Rejected Because**：会丢未保存内容，还会重复发请求。
- **Trade-offs Accepted**：八个面板同时挂着，隐藏的那些也各自发一次初始化请求；分组本来不多，代价可接受。

### Decision D3：分类栏宽度复用现有拖动条 `PaneResizer`

- **Reason**：收件箱、通讯录已经在用这根拖动条，外观和行为都一样（拖动 / 左右方向键 / 双击复位），用户不用重新学。
- **Alternatives Considered**：新写一根拖动条；或干脆固定宽度不可拖。
- **Rejected Because**：新写就是重复造轮子；固定宽度不一定合每个人的习惯。
- **Trade-offs Accepted**：`PaneResizer` 原是为「两栏以上」设计的，这里只用一根，宽度状态自己管（见第 3 节）。

### Decision D4：分类合并与改名

- **Reason**：「启动」和「阅读」内容都很少，各自占一个分类显得空；合并成「通用」更紧凑。
- **Alternatives Considered**：保持九个分类；或把「启动」并进「账号与同步」。
- **Rejected Because**：九个偏多；启动跟账号同步没关系。
- **Trade-offs Accepted**：「通用」里放的是两件不太相干的事（开机启动 + 远程图片），靠小标题分开。

### Decision D5：「默认拦截远程图片」开关落 `settings.json`

- **Reason**：这是全局默认值，跟数据目录、通知开关一样属于「应用设置」，放同一个文件最省事。
- **Alternatives Considered**：存前端本地存储；或存数据库。
- **Rejected Because**：读信判定在后端，前端存储后端读不到；数据库是邮件数据的地方，应用设置不该混进去（现有约定就是这么分的）。
- **Trade-offs Accepted**：要动 `AppSettings` 字段，前后端数据结构和测试都得跟着加一个字段。

## 3. 接口与数据

### 3.1 后端

- `settings.rs`：`AppSettings` 增加字段 `block_remote_images_by_default: bool`，默认 `true`（老配置文件里没这个字段时按 `true` 处理，保证升级后仍是拦截）。
- `commands.rs`：`AppSettingsDto` / `AppSettingsInputDto` 增加同名字段；保存命令带上它。
- `reading.rs`：算「本封是否放行远程图片」时，最前面加一条：全局默认关掉拦截时直接放行。现有的「本封放行」「信任发件人」规则保留不变。

### 3.2 前端

- `api.ts`：`AppSettings` 类型加 `blockRemoteImagesByDefault: boolean`；保存时带上。
- `SettingsWorkspace.tsx`：改成两栏结构；新增左栏选中状态、宽度状态；把八个分类面板按分类组织。
- `index.css`：新增两栏网格、左栏条目、选中态样式。
- `i18n.en.ts`：`人工智能`→`AI功能`、`外部接入`→`MCP`、`阅读设置`/`启动`→`通用`，并新增「默认拦截远程图片」等词条。

### 3.3 本地存储

- 分类栏宽度：键 `ymail.settings-nav-width.v1`，默认 `200`，范围 `[160, 320]`。
- 分类栏选中项：本次运行内记住即可，不落盘；默认选中 `通用`。

## 4. 行为

- 点左栏某个分类：右边换成那一块内容，左栏该项高亮。
- 拖动分类栏右边线：实时改宽度，松手落盘。
- 拖动条聚焦后按左右方向键：按步长改宽；`Home` / `End` 到最小 / 最大；双击复位到 200。
- 窗口变窄：分类栏收到 160，优先保住右边内容宽度。
- 「默认拦截远程图片」开关：
  - 开（默认）：跟现在一样，远程图片一律先拦，信任的发件人除外。
  - 关：远程图片默认直接显示，不再逐封拦。
- 开关改动走现有「保存」按钮（跟通知开关同一套），保存后回读真实生效值。

## 5. 验收标准

- **R1**（MUST）设置页呈现左右两栏：左分类、右内容。
- **R2**（MUST）左栏八个分类，顺序为：通用、外观、账号与同步、代理、AI功能、MCP、存储与通知、通讯录。
- **R3**（MUST）`通用` 分类同时包含「开机自动启动」和「读信与远程图片」两块内容。
- **R4**（MUST）点任一分类，右边立刻显示对应内容，其它分类内容不显示。
- **R5**（MUST）切换分类不丢未保存的表单内容。
- **R6**（MUST）分类栏宽度可拖动；范围 160–320；双击复位到 200；下次打开保持上次宽度。
- **R7**（MUST）分类文案为 `AI功能`、`MCP`、`存储与通知`、`通用`，界面与英文词条一致。
- **R8**（MUST）`通用` 里出现「默认拦截远程图片」开关，默认是开的。
- **R9**（MUST）关掉开关并保存后，重新进读信页，远程图片默认显示；打开并保存后，恢复默认拦截。
- **R10**（MUST）四关（`fmt` / `clippy` / `test` / `build`）加 `npm test` 全绿。

---

## 6. 安全与合规

- 远程图片的**出厂默认仍是拦截**；只有用户显式关掉开关才改行为，开关旁必须给一句风险提示。
- 开关值只存本地 `settings.json`，不入库、不上传。
- 邮件正文仍是不可信内容；本规格不因正文触发任何行为。
- 不动凭据存储方式。
