## 0. 需求溯源（五问）

1. **谁要的**：项目所有者本人。
2. **解决什么已发生的问题**：通知智能识别单封最长等 15 秒，但真实要多久没人量过；继续用云端还是换本地，缺一个实测数字做判断。
3. **不做会怎样**：只能靠猜。改了方案也不知道是变快还是变慢。
4. **怎么算做成**：点一下「检查延迟」，就能看到当前站点与模型识别一封标准测试邮件实际花了多少毫秒。
5. **为什么不是顺手加个计时**：要新增一条手动触发的外发路径，涉及外发内容、授权和审计，不能混进正常识别流程里。

## 1. 目标与边界

### 1.1 本规格包含

- 「AI功能」页「通知智能识别（高级功能）」卡片内新增「检查延迟」按钮。
- 按钮使用卡片里当前选中的站点、模型、思考程度（页面上的草稿值，不要求先点「保存设置」）。
- 点击后先弹确认框，写清站点、模型、是不是本地，并说明发的是系统编的假邮件、不含任何真实邮件。
- 确认后连测 3 次，每测完一次立刻显示结果；最后给出平均耗时。
- 测试邮件内容固定在程序里，不含任何用户真实数据。
- 测试与通知识别开关状态无关：开关关着也能测。

### 1.2 本规格不包含

- 不测本地规则识别的耗时（那是另一件事）。
- 不改动通知识别本身的提示词、超时和校验规则。
- 不读收件箱、不碰任何真实邮件。
- 不做历史记录和趋势图。

## 2. 设计

### 2.1 界面

在「通知智能识别（高级功能）」卡片的按钮行里，紧接着「保存设置」放一个「检查延迟」按钮。

点击时的前置检查（跟打开开关时的判断一致）：

- 没选站点或站点不存在 → 提示「请先选择站点和模型」。
- 站点已停用 → 提示先启用或换一个站点。
- 站点不支持对话（比如 DeepL）→ 提示换一个站点。
- 都通过 → 弹确认框。

确认框复用现有风险确认弹窗的样式，展示：站点、用哪个模型、是不是本地服务，外加一句「会发送一封系统编造的测试邮件，不包含你的任何真实邮件内容」。按钮为「开始测试」和「取消」。

测试中：按钮禁用并显示「测试中…」，每测完一次就把那一次的结果贴出来。

结果展示：

- 每次一行：第几次、耗时多少毫秒、认出验证码没有、认出验证链接没有；失败就写中文原因。
- 最后一行：三次平均耗时。

界面文案保持中英双语，英文补进 `src/i18n.en.ts`。

### 2.2 后端

新增一条命令 `check_notification_latency`，参数：

- `providerId`：站点编号。
- `model`：模型名；留空回退站点默认模型。
- `thinkingLevel`：可选，跟界面草稿一致。

返回：耗时毫秒、是否认出验证码、是否认出验证链接、错误信息（可选）。

后端流程：

1. 按编号取出站点配置和密钥（只读，不写库、不写保险箱）。
2. 用通知识别同一套系统提示词，配固定的测试邮件。
3. 记开始时间，调用现有的对话接口，记结束时间。
4. 用现有本地校验解析模型输出。
5. 返回耗时和识别结果。

要点：

- 超时沿用通知识别的 15 秒，测出来的就是真实会上限。
- 走和正常识别相同的外发路径，并写一条 AI 审计记录，保持「每次外发都留痕」。
- 不写缓存、不写库、不把正文写日志。

### 2.3 测试邮件（固定内容）

- 发件人：Example Security
- 主题：Your verification code
- 正文：您的验证码是 482913，10 分钟内有效。也可以打开 https://example.com/verify?token=abc123 完成验证。

这段内容只用于测试，和任何真实站点无关。

## 3. 安全

- 只发系统编造的固定内容，不含真实邮件，也不含用户输入。
- 每次测试都要用户点按钮并在弹窗里确认，等于每次外发前点头。
- 密钥只从系统保险箱读，不出现在界面和返回结果里。
- 返回结果只给耗时和「认到没认到」，不回显模型原文。
- 失败信息用通用中文提示，不含正文、验证码和完整链接。

---

## 4. 验收标准

- R1：「通知智能识别」卡片里有「检查延迟」按钮。
- R2：没选站点时点击给出中文提示，且不外发（模型留空是允许的，会回退站点默认模型）。
- R3：点击后弹确认框，写清站点、模型、是不是本地。
- R4：点「取消」不发任何请求。
- R5：确认后连测 3 次，每次显示耗时和识别结果。
- R6：显示三次平均耗时。
- R7：通知识别开关关闭时按钮依然可用。
- R8：失败（超时、密钥错、站点不支持）给出中文原因。
- R9：测试内容不含任何用户数据。
- R10：四关全过：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`、`npm run build`。

## 6. 未决 / 未验证

- 连测 3 次是否够：网络抖动大时可能要更多次；先做 3 次，看实际效果再调。
- 真实延迟尚未测过，本规格只保证「能量出来」，不预设结果。
- 本机 Ollama 这类本地站点的耗时口径与云端一致，但含义不同（没有网络往返）；界面不额外区分，由用户按站点自行判断。
