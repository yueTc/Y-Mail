# 邮箱右键「立即同步」— 设计规格

| 项 | 值 |

| 范围 | 收件箱左侧邮箱栏的账号右键菜单 |

---

## 1. 要解决的问题

用户已经能在设置里的同步页手动同步，但日常收信时还要切到设置页。希望在左侧邮箱栏直接右键某个邮箱，选择「立即同步」，只让这个邮箱马上重新拉取一次。

---

## 2. 目标与边界

### 2.1 目标

- 邮箱账号右键菜单新增「立即同步」。
- 点击后只重启被右键点中的这个账号，不影响其它账号。
- 复用同步页现有做法：先停止该账号的同步，再重新启动，确保不等原来的空闲等待结束。
- 同步页、自动同步、单账号同步状态和邮件列表刷新逻辑保持不变。

### 2.2 不做什么

- 不新增后端接口，不改同步协议、凭据、代理或数据库结构。
- 不增加二次确认。这个动作不删除数据，也不发送邮件。
- 不改变设置页的「立即同步」「全部立即同步」和「全部停止」。
- 不在邮箱栏常驻新增按钮。

---

## 3. 交互设计

邮箱账号右键菜单顺序固定为：

1. 全部标为已读
2. 立即同步
3. 编辑
4. 新建文件夹
5. 删除邮箱

点击「立即同步」后：

- 菜单立即关闭。
- 页面短提示显示「正在同步「邮箱名」」，停留 3 秒。
- 该账号重新启动同步；其它账号不停止、不重启。
- 同步成功后，沿用现有同步完成时的账号栏和邮件列表刷新。
- 同步失败时，在收件箱现有的错误提示位置显示可读原因。

如果该账号正在执行同步重启，再右键同一个账号时，「立即同步」保持禁用，避免重复点击。不同账号仍可各自操作。

### 3.1 键盘与边界

- 键盘 Esc、点击菜单外部和滚动时关闭菜单的行为保持现状。
- 菜单靠近窗口边缘时，沿用现有上移或左移逻辑。
- 空白处右键仍只显示「添加邮箱」。

---

## 4. 数据流

1. 用户右键账号，`openAccountMenu` 记录目标账号。
2. 用户点击「立即同步」。
3. 前端关闭菜单，并把目标账号标记为同步重启中。
4. 调用现有 `stopSync(accountId)` 停止该账号。
5. 调用现有 `startSync(accountId)` 重新启动该账号。
6. 重新读取 `syncStatus()`，让顶栏同步徽标立即反映最新状态。
7. 后台同步进入稳定态后，沿用现有的 `syncJustSettled` 逻辑刷新账号栏和邮件列表。

---

## 5. 错误处理

- `stopSync` 或 `startSync` 任一步失败，结束忙碌标记，并复用 `describeError` 给出可读错误。
- 失败不停止其它账号，不修改账号数据，不显示底层凭据或邮件正文。
- 重复点击由界面忙碌标记挡住；后台仍沿用现有单账号单实例约束。

## 7. 验收标准

1. 右键任意邮箱能看到「立即同步」，位置在「全部标为已读」和「编辑」之间。
2. 点击后按顺序调用 `stopSync(账号编号)`、`startSync(账号编号)`，且编号来自被右键的账号。
3. 不调用其它账号的停止或启动操作。
4. 点击后菜单关闭，并显示包含该邮箱名称的短暂提示。
5. 任一步失败时显示错误，忙碌状态能恢复，之后可以再次点击。
6. 空白处右键、文件夹右键、删除邮箱、编辑和新建文件夹的现有行为不变。
7. 通过 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`、`npm run build`。

## 8. 测试范围

- 前端回归：账号菜单出现新选项且顺序固定。
- 前端回归：只对目标账号执行停止后再启动，调用顺序正确。
- 前端回归：成功后菜单关闭并显示短提示。
- 前端回归：失败时显示错误且不会卡住后续操作。
- 回归：空白菜单仍只有「添加邮箱」；文件夹和邮件右键菜单不受影响。
