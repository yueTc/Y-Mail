## 0. 需求溯源

1. **谁要的**：项目所有者本人。
2. **解决什么问题**：
   - 客户端现在只能看文件夹，不能新建、改名、删除，换个文件夹还得去网页端。
   - 看到不要的邮件，客户端里删不掉，也得回网页端。
3. **怎么算做成**：见第 8 节验收标准。
4. **为什么不是只改界面**：操作必须真实作用到服务商，本地库还要跟着对齐，属于协议写操作 + 本地一致性，不是纯界面。

---

## 1. 目标与边界

### 1.1 本规格包含

- 右击邮箱账号 → 「新建文件夹」，在服务商创建，成功后本地文件夹列表同步出现。
- 右击文件夹 → 「重命名」，在服务商改名，成功后本地列表、本地邮件归属同步更新。
- 右击文件夹 → 「删除」，在服务商删除。**文件夹里还有邮件或子文件夹时不允许删除**（用户已确认选「甲」）。
- 不能增删改的文件夹不显示对应入口，或入口置灰不可点。
- 右击单封邮件 → 「删除」，同步到服务商。
- 每次写操作前有确认，写明目标文件夹或邮件；失败给中文可读提示，本地不出现假成功。
- 服务商拒绝时，把原始返回翻译成人话展示，不吞错误、不假装成功。

### 1.2 本规格不包含

- 不做批量选择邮件后一起删。
- 不做拖拽移动邮件到别的文件夹。
- 不做新建子文件夹时的层级选择器；只做「在账号根下建一个」和「在某文件夹下建子文件夹」两种入口（见 3.2）。
- 不做文件夹排序自定义、不做颜色、不做本地虚拟文件夹（统一收件箱、红旗邮件仍是只读虚拟入口）。
- 不改 IMAP / SMTP / OAuth2 认证方式，不改正文安全清洗与远程图片拦截规则。

## 2. 哪些文件夹不开放增删改

判定分两层：本地先挡住明显的，服务商最终还是权威。

### 2.1 本地预判（命中任意一条即不可改）

| 判定 | 原因 |
|---|---|
| 路径是 `INBOX`（不区分大小写） | 收件箱是协议固定入口，不能改名或删除 |
| 归类是 `sent` / `draft` / `trash` / `junk` | 已发送、草稿箱、已删除、垃圾邮件是系统文件夹 |
| 服务器 LIST 属性含 `\Noselect` | 它只是装子文件夹的空壳，本身不能打开 |
| 服务器 LIST 属性含 `\NonExistent` | 服务器声明这个文件夹已不存在 |
| 路径落在 Gmail 的 `[Gmail]` 命名空间下 | Gmail 的系统标签不接受改名 / 删除 |

新建子文件夹不受上表限制：只要父文件夹存在且不是「不能有子文件夹」即可（见 3.2）。

### 2.2 服务商兜底

- 三件写操作都可能被服务商拒绝（权限、套餐、系统文件夹、协议限制）。
- 收到拒绝时：本地不改，界面提示服务商原话对应的中文说明。
- 服务商原文多为英文或协议术语：认得出的翻成对应中文，认不出的给一句通用中文兜底，不把英文原文直接端给用户；原文只进本地日志。
- 服务商的运行时拒绝比 LIST 属性更权威：`CREATE` 被明确告知「这个位置不能再分层」时，把这条结论记到父文件夹上（`folder.child_create_blocked`），下次右键不再显示「新建子文件夹」，改成一条置灰的中文说明。
- 不把「服务商拒绝」当成 bug，也不重试到成功为止。

### 2.3 落地要求

- `folder` 表新增一列保存服务器 LIST 属性，本地才能判断上面的规则。
- 同步文件夹列表时把属性一起写进库。
- `folder` 表另存一列运行时结论：被服务商拒绝过建子文件夹的父文件夹标记 `child_create_blocked`；同步重新对齐时该标记不丢。

## 3. 新建文件夹

### 3.1 入口

- 右击邮箱账号 → 「新建文件夹」：在账号根下创建。
- 右击任意文件夹 → 「新建子文件夹」：在这个文件夹下创建。
- 是否给「新建子文件夹」入口只看服务器能力：服务器没说不能再分层就给，系统文件夹也一样（用户已确认「跟着服务器来」）；只有服务器标了 `\NoInferiors`（明确不能再分层）或 `\Noselect`（只是空壳）时才不给。**若真发 `CREATE` 仍被拒绝（见 2.2），以这次拒绝为准，本地收起该入口。**

### 3.2 行为

1. 弹输入框，让用户填名字。
2. 校验：
   - 去首尾空格后不能为空。
   - 不能包含服务器层级分隔符（通常是 `/`，以该文件夹的 `delimiter` 为准）；填了要提示改用「新建子文件夹」。
   - 同层级不能重名。
3. 名字按 IMAP 要求编码成 Modified UTF-7 后发 `CREATE`。
4. 成功后重新拉一次服务器文件夹列表，本地对齐；新文件夹自动出现在侧栏。
5. 失败按 2.2 处理。

### 3.3 交互细节

- 操作期间按钮禁用，显示「正在同步到服务器…」。
- 成功后给一条短提示，例如「已新建文件夹」。
- 用户取消输入不产生任何请求。

## 4. 重命名文件夹

### 4.1 入口与行为

1. 右击可改文件夹 → 「重命名」。
2. 输入框预填当前名字（只填末段名字，不填整条路径）。
3. 校验规则同 3.2 的第 2 条。
4. 发 `RENAME 旧服务器名 新服务器名`，名字同样按 Modified UTF-7 编码。
5. 成功后：
   - 重新拉服务器文件夹列表并对齐本地。
   - 本地该文件夹的显示名、服务器名一起更新。
   - 文件夹下面的邮件归属不变，不重复、不丢失。
6. 若服务商是 Gmail 这类「重命名会级联改名子文件夹」的实现，以服务器返回后的列表为准，本地整体对齐。

### 4.2 失败处理

- 服务商拒绝：本地保持原样，提示中文原因。
- 目标名字已存在：本地先拦一次，服务商再报错也照原话提示。

## 5. 删除文件夹（用户已确认：甲方案）

### 5.1 入口

- 右击可改文件夹 → 「删除」。
- 收件箱、系统文件夹、带 `\Noselect` 的文件夹不提供该项。

### 5.2 删除前检查（全部在服务商侧确认）

1. **文件夹里有邮件**：`SELECT` 该文件夹，服务器 `EXISTS` 大于 0 → 拒绝删除，提示「这个文件夹里还有 N 封邮件，先清空或移走再删」。
2. **文件夹里有子文件夹**：从最新 LIST 结果看，存在以「本文件夹路径 + 分隔符」开头的其它文件夹 → 拒绝删除，提示「先把里面的子文件夹删掉」。
3. 两项都为空才允许继续。

### 5.3 行为

1. 弹确认框，写明要删的文件夹名。
2. 发 `DELETE`。
3. 成功后重新拉服务器列表并本地对齐；本地该文件夹记录和它下面的邮件记录一并清理。
4. 失败按 2.2 处理，本地一律不变。

### 5.4 不做的事

- 不提供「连邮件一起删」。
- 不自动清空文件夹。
- 不自动递归删子文件夹。

## 6. 删除单封邮件

### 6.1 入口

- 邮件列表里右击一封邮件 → 「删除」。
- 统一收件箱、单账号文件夹、已删除文件夹里都可用。

### 6.2 语义（按主流邮箱客户端习惯）

| 邮件所在位置 | 删除行为 |
|---|---|
| 不在「已删除」文件夹，且账号有已删除文件夹 | 「移到已删除」：服务商支持 `MOVE` 扩展就发 `UID MOVE`，否则用 `COPY` + `UID STORE +FLAGS \Deleted` + `EXPUNGE` 回退 |
| 不在「已删除」文件夹，账号没有已删除文件夹 | 弹二次确认，确认后彻底删除 |
| 已在「已删除」文件夹 | 弹二次确认，确认后彻底删除 |

- 「彻底删除」= `UID STORE +FLAGS \Deleted` 后 `EXPUNGE`。
- 二次确认框写清楚「服务器上会真的删除，找不回来」。
- 不做「只在本机隐藏」这种假删除。

### 6.3 本地一致性

服务器确认成功后，本地必须主动处理，不能只等下一次同步：

- 彻底删除：删掉本地那条邮件记录，并刷新所在文件夹未读数。
- 移到已删除：本地先移除原文件夹那条记录，再触发该账号一次增量同步；服务商已删除文件夹里的那封邮件按正常同步入库。
- 服务器操作失败：本地记录不动，列表不消失，提示失败原因。

> 背景：现有同步只处理新增和标志变化，不感知服务器端 `EXPUNGE`，所以删除链路的本地处理必须由删除命令自己完成。

### 6.4 不做的事

- 不做批量删除。
- 不做「永久删除」以外的回收站二次恢复。
- 不弹出「是否同时删除服务器副本」这种反直觉选项。

## 7. 协议与数据层要求

### 7.1 IMAP 层新增能力

- `CREATE mailbox`
- `RENAME old new`
- `DELETE mailbox`
- `UID MOVE`（能力探测）
- `UID COPY`
- `UID STORE +FLAGS.SILENT (\Deleted)`
- `EXPUNGE`
- 文件夹名统一走 Modified UTF-7 编码；现有编码函数目前只在测试里用，要提升为正式实现。
- 路径含引号、反斜杠、中文时正确转义。

### 7.2 本地库

- `folder` 表新增服务器属性列（迁移 0014）。
- `folder` 表新增「被服务商拒绝建子文件夹」标记列（迁移 0015）；运行时拒绝落盘，同步不覆盖。
- 删除文件夹成功后清理本地 `folder` 行；邮件记录随外键级联清理。
- 重命名成功后按服务器原始名对齐，保留邮件归属。
- 删除单封邮件按 6.3 处理。

### 7.3 同步与并发

- 写操作与后台同步同时进行时，以服务器最后一次 LIST 结果对齐。
- 写操作成功后触发目标账号一次列表刷新 / 增量同步。
- 同一账号的文件夹写操作串行执行，避免两个改名命令互相覆盖。

## 8. 界面与验收标准

### 8.1 界面

- 账号右键菜单新增「新建文件夹」。
- 文件夹右键菜单新增「重命名」「删除」；不可改的文件夹这两项不出现或置灰。
- 邮件右键菜单新增「删除」。
- 操作中显示进行状态；成功给短提示；失败给中文原因。

### 8.2 验收标准

1. 右击邮箱能新建文件夹，网页端能看到，客户端刷新后也能看到。
2. 右击自定义文件夹能改名，网页端名字跟着变，本地邮件不掉。
3. 文件夹里有邮件时删不掉，提示说得清有几封。
4. 文件夹里有子文件夹时删不掉。
5. 空的自定义文件夹能删掉，网页端和客户端都消失。
6. 收件箱、已发送、草稿箱、已删除、垃圾邮件不出现增删改入口。
7. 普通文件夹里右击邮件 → 删除，邮件出现在已删除，原位置消失。
8. 已删除文件夹里右击邮件 → 删除，二次确认后服务端真删，客户端也消失。
9. 服务商拒绝时本地不出现假成功，提示能看懂。
10. 以上操作在断网、授权码失效时都有可读提示，不崩、不卡死。

## 9. 用户已确认（原待确认项）

1. 删除文件夹采用甲方案：文件夹里还有邮件或子文件夹时拒绝删除，不自动清空、不递归（第 5 节）。
2. 删除单封邮件语义按第 6.2 节执行：普通文件夹「移到已删除」；已在已删除、或账号没有已删除文件夹时，二次确认后彻底删除。
3. 子文件夹允许做：右击账号 → 新建根文件夹；右击文件夹 → 新建子文件夹。入口按服务器能力显示，服务器允许分层就给，系统文件夹也一样（第 3.1 节）。
