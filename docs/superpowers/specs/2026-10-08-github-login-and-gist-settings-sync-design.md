## 0. 需求溯源

1. **谁要的**：项目所有者本人。
2. **解决什么问题**：
   - Y-Mail 现在是纯本地应用，换一台电脑或重装系统，邮箱账号、授权码、代理、签名、AI 站点和密钥都得重填一遍。
   - 软件里没有用户身份，头像和昵称没有来源。
3. **不做什么会怎样**：多设备用户每换一台机器就重复劳动；授权码填错还得自己排查半天。
4. **怎么算做成**：见第 5 节验收标准（R1–R16）。
5. **为什么不能图省事**：要同步的东西里包含邮箱授权码和 AI 接口密钥。只要上传过一次明文，等于把用户所有邮箱的钥匙挂到网上。所以「怎么加密、钥匙存哪、忘了怎么办」必须在实现之前一次说清。

## 1. 目标与边界

### 1.1 本规格包含

- GitHub 账号登录：只用来取昵称和头像，登录后显示在界面上。
- 「设置同步」开关：用户自定一个同步密码，把选定的配置加密后存进一个私密 Gist。
- 多设备互通：改动后自动加密上传；每次启动自动拉一次；两台设备改动冲突时弹窗让用户选。
- 同步范围（进包）：
  - 邮箱账号：显示名、邮箱地址、登录名、收信/发信服务器的主机、端口、加密方式、认证方式、代理模式、颜色、启用状态，以及 Gmail/Outlook 的「服务商标识」和「客户端编号」（这两样不是秘密）。
  - 账号授权码：QQ、163 这类密码制邮箱的凭据。
  - 代理：代理条目的名称、类型、主机、端口、用户名，以及代理密码。
  - 全局代理设置（系统代理 / 直连 / 指定代理）。
  - 签名。
  - 界面与行为开关：新邮件系统通知、通知智能识别、默认拦截远程图片、关闭键收托盘、启动时静默进托盘。
  - AI：站点列表（名字、类型、接口地址、默认模型、可选模型清单、思考程度、启用开关）、功能级模型映射（翻译/摘要/润色/起草各用哪个站点和模型），以及每个站点的接口密钥。
- 不进包：邮件正文、已读状态、草稿、附件、联系人、Gmail/Outlook 的登录令牌、AI 翻译缓存、AI 调用审计日志。
- 每台机器自己的东西，**绝不同步**：邮件数据目录、旧附件目录、待清理目录、GitHub 令牌、同步密码本身。

### 1.2 本规格不包含

- 不建服务器、不注册用户、不收费用。所有网络请求只发往 GitHub。
- 不做跨设备实时同步；不做后台常驻轮询（只在启动时和改动后动作）。
- 不做同步密码找回、恢复码、密保问题。
- 不做冲突的自动合并（只让用户选一边）。
- 不做联系人、日历、邮件内容的同步。
- 不做多 GitHub 账号并存（同一时间只认一个）。
- 不动现有「同步状态」面板。那个面板管的是邮件收发同步，跟本功能的「设置同步」是两回事，界面文案必须能一眼分开。

## 2. 架构决策（含反选理由）

### Decision D1：GitHub 登录只当身份和头像，不当同步钥匙

- **Reason**：GitHub 账号和邮箱账号是两个东西；GitHub 也解不开同步数据，钥匙只能是同步密码。
- **Alternatives Considered**：把 GitHub 账号当唯一身份，同步数据全挂在它下面。
- **Rejected Because**：GitHub 账号一旦出问题，配置就全没了；而且邮箱授权跟 GitHub 没有关系。
- **Trade-offs Accepted**：用户可能要操作两回——GitHub 登录一次，各个邮箱账号再各自授权。

### Decision D2：同步通道用 Gist，不建服务器

- **Reason**：零成本、零运维，用户自己就能在网页上看和管理这个 Gist。
- **Alternatives Considered**：自建服务端；或借用网盘 / WebDAV。
- **Rejected Because**：自建要花钱要运维；网盘接口各家不同，适配成本高。
- **Trade-offs Accepted**：私密 Gist 只是「搜不到」，不是真正的私有——知道网址的人就能看到内容。所以上传的必须从头到尾都是密文（见第 6 节）。

### Decision D3：钥匙只认同步密码，不给找回

- **Reason**：没有服务器就没有安全的「找回」通道；任何找回方式都等于多开一个能解密的口子。
- **Alternatives Considered**：恢复码；邮箱验证码；把密码也存进 Gist。
- **Rejected Because**：恢复码用户会丢会拍照；存进 Gist 等于没锁。
- **Trade-offs Accepted**：忘了就只能重设；重设会新建一个 Gist 并把旧的删掉。

### Decision D4：GitHub 权限分两步要

- **Reason**：只想要头像的人，不该被迫交出「管理你所有 Gist」这么大的权限。
- **Alternatives Considered**：登录时一次要全。
- **Rejected Because**：权限过大，用户看到会不安，也不合最小权限原则。
- **Trade-offs Accepted**：点开同步功能时可能再弹一次 GitHub 授权页，要多点一次。

### Decision D5：冲突不静默覆盖

- **Reason**：一冲突可能就是授权码没了，这种事不能悄悄替用户做决定。
- **Alternatives Considered**：最后改的赢，直接覆盖。
- **Rejected Because**：静默丢配置不可接受。
- **Trade-offs Accepted**：偶尔会弹一个选择框打扰用户。

### Decision D6：改动自动传，启动自动拉

- **Reason**：用户不用记着点按钮，两台设备自然就一致。
- **Alternatives Considered**：全靠手动点；或只自动拉、手动推。
- **Rejected Because**：容易忘，忘了就不一致。
- **Trade-offs Accepted**：每次改配置都会产生一次 Gist 更新，Gist 的历史版本会累积（历史里也都是密文）。

### Decision D7：AI 密钥进包，但落盘只进系统保险箱

- **Reason**：不进包新设备就得逐个重填；而落进数据库又违反安全铁律。
- **Alternatives Considered**：AI 密钥不同步，其余配置同步。
- **Rejected Because**：用户已明确选「甲」——连密钥一起同步。
- **Trade-offs Accepted**：任何一台解开过同步密码的设备，都能拿这些密钥去请求 AI 服务。界面上必须把这条讲明白（见第 6 节）。

### Decision D8：GitHub 登录走设备码流程（无浏览器回调）

- **Reason**：GitHub 的授权应用目前不支持 PKCE，官方给桌面程序推荐的是设备码流程：程序显示一串码，用户在浏览器里输入并确认。
- **Alternatives Considered**：回环回调 + PKCE（跟现在的谷歌/微软登录一致）。
- **Rejected Because**：这条路 GitHub 走不通。
- **Trade-offs Accepted**：用户要多一步手动输入代码，不像点一下就弹回来。
- **备注**：实现前按 GitHub 最新文档再核对一次；若届时已支持 PKCE，可改走回环回调，复用现有代码。

## 3. 详细设计

### 3.1 同步范围一览

| 数据 | 现有位置 | 进包？ | 说明 |
|---|---|---|---|
| 邮箱账号 | `account` 表 | 是 | 不含任何明文凭据列 |
| 账号授权码 | 系统保险箱 | 是 | 只进密文包，导入后写回本机保险箱 |
| 代理条目 | `proxy` 表 | 是 | 含主机、端口、用户名 |
| 代理密码 | 系统保险箱 | 是 | 同上 |
| 全局代理设置 | `setting` 表 `proxy.global_*` | 是 | |
| 签名 | `signature` 表 | 是 | |
| 界面/行为开关 | `settings.json` | 部分 | 见 3.2 |
| AI 站点 | `ai_provider` 表 | 是 | `api_key_ref` 只是引用键，本体在保险箱 |
| AI 站点密钥 | 系统保险箱 | 是 | |
| AI 功能映射 | `ai_model_map` 表 | 是 | |
| 邮件正文 / 已读 / 草稿 / 附件 | 数据库与文件 | 否 | |
| 联系人 | `contact` 表 | 否 | |
| Gmail/Outlook 令牌 | 系统保险箱 | 否 | 新设备重新授权一次 |
| AI 缓存 / 审计 | `ai_cache` / `ai_audit` | 否 | 本机数据 |

### 3.2 界面开关里哪些进包

| `settings.json` 字段 | 进包？ | 理由 |
|---|---|---|
| `notifyNewMail` | 是 | 行为开关 |
| `notifyAiEnabled` | 是 | 行为开关 |
| `blockRemoteImagesByDefault` | 是 | 行为开关 |
| `minimizeToTrayOnClose` | 是 | 行为开关 |
| `startMinimizedToTray` | 是 | 行为开关；虽与开机习惯有关，但用户选了统一同步 |
| `dataDir` | 否 | 每台机器路径不同，且它决定数据库开在哪，同步等于自杀 |
| `attachmentDir` | 否 | 同上，仅读兼容 |
| `pendingCleanupDir` | 否 | 本机临时状态 |
| 同步密码 / GitHub 令牌 | 否 | 只存本机保险箱 |

### 3.3 加密方案

- **口令派生**：Argon2id。随机盐 16 字节；内存 64 MiB；迭代 3 次；并行度 1。参数随包一起存，日后可升级。
- **加密**：AES-256-GCM。每次上传都用新的随机 12 字节随机数，绝不复用。
- **明文边界**：只有密文和下面这些"非要露出来不可"的头部信息出网（`format` / `schemaVersion` / `kdf` 参数 / `salt` / `nonce` / `revision` / 设备标识 / 时间）。其余一律在密文里。
- **内存中的明文**：解密后只在内存里存在必要的时间；写回数据库或保险箱后立即释放。日志、错误信息、崩溃信息一律不得带出明文。
- **依赖**：需要新增 Argon2 与 AES-GCM 两个加密库（走 Rust 现成实现，不自造算法）。

### 3.4 同步包内容（加密前的明文结构）

```json
{
  "schemaVersion": 1,
  "deviceId": "本机随机标识",
  "deviceLabel": "本机可读名，默认取主机名",
  "revision": 12,
  "updatedAt": "2026-10-08T12:00:00Z",
  "settings": {},
  "accounts": [],
  "proxies": [],
  "globalProxy": {},
  "signatures": [],
  "aiProviders": [],
  "aiModelMap": [],
  "secrets": {
    "account:qq-123@qq.com": "授权码明文",
    "proxy:公司代理": "代理密码明文",
    "ai:deepseek": "接口密钥明文"
  }
}
```

- `secrets` 用"逻辑键"而不是数据库自增编号，避免各设备编号对不上。
- 导入时的匹配规则：账号按邮箱地址找（表上本来就有唯一约束）；代理按 `标签 + 主机 + 端口` 找；AI 站点按 `标签` 找；签名按名称找。找到就更新，找不到就新建。

### 3.5 Gist 上的文件（出网内容）

Gist 里只放**一个**文件，文件名固定 `ymail-sync.json`；Gist 的说明固定为 `Y-Mail 设置同步`，用来在账号里认出它。Gist 必须是私密的。

```json
{
  "format": "ymail-settings-sync",
  "schemaVersion": 1,
  "kdf": "argon2id",
  "kdfParams": { "m": 65536, "t": 3, "p": 1 },
  "salt": "base64",
  "nonce": "base64",
  "ciphertext": "base64",
  "deviceId": "本机标识",
  "deviceLabel": "本机可读名",
  "revision": 12,
  "updatedAt": "2026-10-08T12:00:00Z"
}
```

外层这几个字段是明文，目的是不用解密就能判断"是不是同一个包""谁改的""要不要冲突处理"。代价是透露了一点元信息（有几台设备、改了多少次），可以接受。

### 3.6 流程

**第一次开启（本机）**

1. 用户在设置页「账号与同步」里点「开启设置同步」。
2. 若还没登录 GitHub，先走设备码登录（见 3.7）。
3. 提示需要「管理你的 Gist」权限，用户同意后再授权一次。
4. 让用户设同步密码：两次输入须一致，至少 8 位。界面上写清"忘了只能重设"。
5. 生成设备标识；把当前配置打包、加密；创建一个私密 Gist，写入密文。
6. 把同步密码、GitHub 令牌存进系统保险箱；把 Gist 编号、设备标识、当前版本号存进数据库。
7. 界面显示「已开启」，列出上次同步时间和 Gist 链接。

**新设备接入**

1. 装好软件，登录**同一个** GitHub 账号。
2. 程序列出该账号下的 Gist，按说明和文件名找到那一个。找不到就提示"没有找到同步数据"。
3. 让用户输同步密码。
4. 拉取、解密、比对版本。
5. 按 3.4 的匹配规则导入；密钥写回本机保险箱。
6. 导入过程中如果发现本机已有同邮箱账号或同标签代理，弹一次确认再覆盖，不静默盖。

**日常同步**

- 触发一：改配置（保存设置、增改账号、改代理、改签名、改 AI 配置）成功后，后端标记一个"待同步"，静默等 5 秒把多次改动并成一次上传。
- 触发二：每次启动、主窗口就绪后，拉一次远端。
- 上传前一律先拉一次远端比对版本号，避免盲目覆盖。
- 上传失败不反复重试，记下错误，界面上给一条提示，下次触发再试。

**冲突处理**

- 本机记着"上次见到的远端版本号"。
- 拉回来发现远端版本号比本机记录的大，而且作者不是本机——判定为冲突。
- 弹窗说明"另一台设备（名字）在某个时间改过设置"，给两个按钮：「用对方的」「用我这台的」。
- 用户选「用对方的」：直接导入远端，覆盖本机配置。
- 用户选「用我这台的」：把本机版本号加一，重新加密上传，覆盖远端。
- 绝不自动替用户决定。

**重设同步密码**

- 在**还有本机数据**的设备上操作：输入新密码 → 用新密码重新加密打包 → 创建一个新的私密 Gist → 删掉旧 Gist。
- 旧 Gist 删除失败（比如网络抖动）时，明确告诉用户"旧 Gist 可能还在，请到 GitHub 上手动删掉"，并给出链接。
- 所有设备都把本地数据丢光了，就只剩"重新添加邮箱"这条路，本规格不提供别的兜底。

**关闭同步**

- 关掉后本机不再自动上传，保险箱里的同步密码和 GitHub 令牌一并清掉。
- 默认**不**删除远端 Gist；另给一个勾选项"同时删掉云端那份"，勾了才删。

### 3.7 GitHub 登录（设备码流程）

1. 程序向 GitHub 申请一组设备码和用户码，显示用户码并打开浏览器。
2. 用户在浏览器里输入用户码、确认授权。
3. 程序轮询结果，拿到访问令牌后存进系统保险箱。
4. 再用令牌取一次用户资料（登录名、昵称、头像地址），存到数据库。
5. 头像地址由界面直接加载；同时在本机缓存一份，避免每次开界面都请求网络。这是全程序唯一一处放行的远程图片，因为它是用户自己触发的身份展示，且来自固定域名。

- 要头像和昵称只申请 `read:user`。
- 开启设置同步时，再申请一次 `gist`。
- 「退出登录」清掉令牌和缓存的头像。

### 3.8 凭据与密钥存放

| 东西 | 存哪 | 键名约定 |
|---|---|---|
| GitHub 访问令牌 | 系统保险箱 | `sync/github-token` |
| 同步密码 | 系统保险箱 | `sync/password` |
| 账号授权码 | 系统保险箱（沿用现状） | `account/<逻辑键>` |
| 代理密码 | 系统保险箱（沿用现状） | `proxy/<逻辑键>` |
| AI 站点密钥 | 系统保险箱（沿用现状） | `ai/<逻辑键>` |

- 复用现有的保险箱封装（含长凭据分片能力），不新写一套。
- 数据库里只允许出现这些引用键，绝不允许出现密钥本体。

### 3.9 后端改动

- 新增一个专门负责本功能的 crate（暂定 `crates/mail-sync`），职责：口令派生与加解密、GitHub 接口调用、Gist 读写、版本与冲突判定。拆成单独的 crate 是为了让加解密这块能被单独测、单独审。
- `mail-core` 增加"导出快照 / 按快照导入"两个能力，并负责在写操作成功后打待同步标记。
- `src-tauri` 增加命令：登录开始 / 登录轮询 / 退出登录 / 取资料 / 同步状态查询 / 开启同步 / 关闭同步 / 立即同步 / 重设密码 / 新设备加入 / 解决冲突。
- 同步状态（设备标识、Gist 编号、当前版本号、上次同步时间、上次错误）放现有 `setting` 表，不新建迁移。
- 启动流程里，在主窗口就绪后拉起一次"拉取并比对"。

### 3.10 前端改动

- 新增一个「设置同步」面板，放在设置页的「账号与同步」分类里，跟现有的「同步状态」（邮件收发）上下分开、标题写清楚，避免用户混淆。
- 面板内容：GitHub 登录状态和头像、开启/关闭开关、同步密码设置、上次同步时间、立即同步按钮、Gist 链接、错误提示、冲突选择框。

## 6. 安全与合规

- **只出密文**：发往 GitHub 的内容只有 3.5 里那几个明文头部字段，其余全是密文。
- **钥匙只在本机**：同步密码和 GitHub 令牌只进系统保险箱；数据库、日志、报错里都不许出现明文。
- **日志脱敏**：涉及同步的日志只记动作、版本号、状态，不记包内容、不记密码、不记令牌。
- **私密 Gist 不是真私有**：界面开启时要用一句大白话告诉用户——"GitHub 的私密 Gist 只是不让别人搜到，拿到网址的人就能看到内容。我们上传的是密文，所以看不到你的邮箱密码，但这一点你要知道"。
- **AI 密钥同步的风险告知**：开启时明确提示"AI 密钥会一起同步；任何一台解开过同步密码的设备都能用这些密钥对外请求 AI 服务"。
- **AI 外发仍要点头**：同步密钥不改变"每次外发前必须用户确认、AI 默认关闭"这条既有铁律。
- **邮件正文仍不可信**：本规格不因邮件正文触发任何同步、发信或跳转。
- **不落明文**：加密密钥只在内存与保险箱中出现；数据库只存引用键。
