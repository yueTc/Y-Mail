## 1. 目标

- 同步状态里，每个账号那行文字改成「已同步 XX 封 / 共 XX 封」，拉取时实时往上涨。
- 「共 XX 封」= 服务器上该账号全部可同步文件夹（收件箱、已发送、草稿、垃圾、已删除、自定义）的邮件总数。
- 「已同步 XX 封」= 本机已经落库的该账号邮件条数。
- 同步完成后保留这行数字，不再变回「等待新邮件」。

## 2. 非目标

- 不做百分比进度条，不加每个文件夹的细分进度。
- 不新增用户可调的同步范围设置项。
- 不改同步失败、授权失效时的提示口径（仍显示原来的出错文字）。
- 不改邮件正文、写信与 AI 任何行为。

## 3. 设计

### 3.1 同步范围改为「全部历史」

- 现在后台补齐范围默认是「近一年」（`SyncConfig::history_range`），用户看不到也改不了。
- 本规格把它改成「全部历史」：补齐下界 `floor = 1`，一直往更早补到没有为止。
- 断点仍按文件夹的 `synced_min_uid` 记录，一次连接只补有界几批（每轮最多 8 批 × 每批 300 封），补不完下次进 IDLE 后接着补。

### 3.2 同步开始时先数总数

- 登录成功、列出文件夹、对齐文件夹之后，对每个「可同步文件夹」（滤掉带 `\NoSelect` 的空壳）做一次 `SELECT` + `UID 1:*` 搜索，取返回 UID 条数，累加得到账号级总数。
- 统计期间该账号状态显示「正在统计邮件总数……」，`total` 先按 0 处理。
- 总数只统计一次（每次新连上算一轮），同步过程中不再重复统计。
- 统计失败（某个文件夹打不开或搜索报错）时，该文件夹按 0 计，不因此中断整轮同步；总数宁可少算也不让同步卡住。

### 3.3 已同步数怎么算

- `progress` = 本地该账号的邮件条数，每写完一批邮件后从库里重新查一次。
- 用「本地条数」而不是「本轮新插入条数」，这样重复同步、重启续传时数字都是对的。
- 展示时取 `min(本地条数, 服务器总数)`，避免本地保留了服务器已删的邮件导致「已同步」超过「共」。

### 3.4 状态文字

- 拉取中、补齐中、等待新邮件时，那行详情统一显示「已同步 X 封 / 共 Y 封」。
- 状态徽标（如「正在同步」「等待新邮件」）保留，用来表示当前在干什么；被替换的是下面那行详情文字。
- 出错 / 需要重新授权时，详情仍显示原来的错误说明与重试提示，不显示进度数字。

### 3.5 撞到本机上限

- 程序原有保护：单账号最多 10 万封、约 4GB。
- 撞上限后不再落盘，`progress` 会停住。此时详情文字改成「已达本机上限（已同步 X 封 / 共 Y 封）」，并继续推进断点，不再反复重试同一批。

## 4. 验收标准

- R1（MUST）后台同步时，同步状态里该账号显示「已同步 XX 封 / 共 XX 封」。
- R2（MUST）「共 XX 封」等于服务器上该账号全部可同步文件夹的邮件总数之和。
- R3（MUST）拉取过程中数字会涨；拉完后停在「已同步 Y 封 / 共 Y 封」，不再变回「等待新邮件」。
- R4（MUST）同步范围改成全部历史，旧邮件会被继续补齐（受单账号 10 万封 / 4GB 上限保护）。
- R5（MUST）同步失败或需要重新授权时，仍显示原来的错误提示，不显示过期进度数字。
- R6（MUST）四关（fmt / clippy / test / build）加 `npm test` 全绿。

## 5. 安全与合规

- 只走原有 IMAP 连接读取文件夹与 UID 列表，不新增任何第三方网络请求，不外发邮件内容。
- 总数与已同步数只存在内存状态快照里，不写数据库，不写日志。
- 邮件正文仍是不可信内容，本规格不因正文触发任何行为。

## 6. Tasks

- T1（后端）`SyncConfig::default().history_range` 改成全部历史；确认补齐下界与断点续传仍正确。
- T2（后端）同步会话开始处新增「数总数」步骤：逐个可同步文件夹 `SELECT` + `UID 1:*`，累加成账号 `total`；期间状态显示「正在统计邮件总数……」。
- T3（后端）进度复用已有的 `count_account_messages(account_id)`（库里已有，`insert_metas` 也在用），不新增重复查询方法。
- T4（后端）每批写入后用本地条数刷新 `progress`；`live_loop` 的「等待新邮件」不再把 progress / total 清零。
- T5（后端）撞上限后状态文字改成「已达本机上限……」，断点照常推进。
- T6（前端）同步面板详情文字改成「已同步 {0} 封 / 共 {1} 封」，`i18n.en.ts` 补英文；总数未知时显示「正在统计邮件总数……」。
- T7（测试）后端：总数统计累加、进度按本地条数刷新、撞上限文字；前端：进度文字与总数未知时的文案。
- T8 四关 + `npm test`；真机看新电脑首同步的实际数字与耗时。
- T9 更新 `.ai-memory`（handoff / project_memory / 当日 daily）。

## 7. 未决与未验证

| 编号 | 类型 | 内容 | 处理 |
|---|---|---|---|
| N1 | 待验 | 大邮箱（几万封）上 `UID 1:*` 一次搜索的耗时与应答大小。 | 代码按规格实现，真机首次同步时观察 |

| N4 | 已知限制 | 部分服务器对已删除 / 垃圾文件夹的 UID 计数口径不同，总数可能与实际略差。 | 以服务端搜索结果为准 |
