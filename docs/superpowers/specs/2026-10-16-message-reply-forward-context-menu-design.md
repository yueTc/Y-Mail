# 邮件回复与转发迁移到右键菜单设计

## 背景

收件箱顶部工具栏目前同时放着“写邮件”“回复”“转发”。邮件列表已经支持右键菜单，菜单中包含分类和删除操作。用户希望把回复和转发改到邮件右键菜单，减少工具栏上的常驻操作。

## 目标

- 邮件列表、会话行和搜索结果的右键菜单都提供“回复”和“转发”。
- 点击菜单项后，沿用现有写信窗格和原邮件预填逻辑。
- 回复、转发只针对右键点中的邮件，不依赖当前选中状态。
- 移除工具栏中的“回复”和“转发”按钮。
- 保留“写邮件”、刷新、筛选和同步等其他工具栏功能。

## 交互设计

邮件右键菜单中的顺序为：

1. 回复
2. 转发
3. 立即分类
4. 手动分类
5. 删除

菜单项点击后立即关闭右键菜单并打开写信窗格。回复传入 `kind: "reply"`，转发传入 `kind: "forward"`，两者都使用当前菜单记录的 `sourceMessageId`。

会话行右键时，沿用现有菜单目标解析，使用会话最新邮件；普通邮件行和搜索结果使用当前行对应邮件。右键菜单的关闭、键盘 Esc、滚动和窗口变化行为保持现状。

## 实现边界

- 修改 `src/InboxPanel.tsx` 的邮件右键菜单和顶部工具栏。
- 不修改写信窗格、接口类型、发送队列或后端逻辑。
- 不新增菜单组件；复用现有 `messageMenu` 状态和 `setComposeRequest`。
- 不改变邮件正文、收件人、主题、引用关系等预填规则。

## 数据流

1. 用户在邮件行上右键。
2. `openMessageMenu` 保存目标邮件及菜单坐标。
3. 用户点击“回复”或“转发”。
4. 菜单动作使用 `messageMenu.message.id` 调用 `setComposeRequest`。
5. `ComposePanel` 按现有 `ComposeRequest` 逻辑读取原邮件并生成预填内容。
6. 菜单关闭，用户继续编辑或发送。

## 错误处理

本次改动不新增异步操作，也不改变现有错误处理。若写信窗格后续读取原邮件失败，继续由现有写信流程显示错误；右键菜单的关闭行为保持不变。

## 测试

在现有收件箱测试中增加回归覆盖：

- 右键邮件能看到“回复”和“转发”。
- 点击“回复”会打开回复写信窗格并使用当前邮件编号。
- 点击“转发”会打开转发写信窗格并使用当前邮件编号。
- 工具栏不再渲染“回复”和“转发”按钮。
- 现有分类、删除和写邮件入口继续可用。

## 验收标准

- 右键任意邮件后可以直接回复或转发。
- 回复和转发不需要先单击选中邮件。
- 工具栏只保留新建邮件入口，不出现重复的回复、转发按钮。
- `cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`、`npm run build` 全部通过。
