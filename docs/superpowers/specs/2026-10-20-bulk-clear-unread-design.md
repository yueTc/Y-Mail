# 邮箱与文件夹批量清除未读设计

| 项 | 值 |
|---|---|
| 日期 | 2026-10-20 |
| 状态 | 已确认 |
| 范围 | 邮箱栏右键菜单、批量已读接口、未读计数刷新 |
| 关联规格 | `docs/superpowers/specs/2026-10-03-unified-inbox-client-design.md`、`docs/superpowers/specs/2026-10-05-inbox-ui-optimization-design.md` |

## 1. 背景与目标

用户需要快速清除未读状态：

- 邮箱账号右键时，清除该账号所有文件夹里的未读。
- 文件夹右键时，只清除该文件夹里的未读。

操作只改本机数据库，不联网，也不回写服务器。

## 2. 需求

### R1 邮箱账号入口

邮箱账号右键菜单 MUST 新增「全部标为已读」。

- 点击后 MUST 先显示确认框，并说明只改本机、不回写服务器。
- 确认范围是该账号下的所有文件夹，包括收件箱、已发送、草稿箱、垃圾邮件、已删除和自定义文件夹。
- 取消确认 MUST NOT 调用批量接口，也不得改动任何邮件。
- 确认后 MUST 关闭右键菜单并执行批量操作。

### R2 文件夹入口

文件夹右键菜单 MUST 新增「全部标为已读」。

- 范围只限当前文件夹，不得影响同一账号的其它文件夹。
- 文件夹操作 MUST 直接执行，不增加二次确认。
- 执行后 MUST 关闭右键菜单。

### R3 本地状态

批量操作 MUST 只修改本机数据库。

- MUST NOT 发起任何网络请求。
- MUST NOT 修改服务器 Seen 状态或产生待回写的服务器同步任务。
- 现有单封邮件打开后标已读的行为保持不变。

### R4 原子性

批量操作 MUST 在一个数据库事务里完成。

- 先把目标范围内所有未读邮件改为已读。
- 再按邮件实际状态重新计算受影响文件夹的未读数。
- 任一写入失败时 MUST 整体回滚，不能留下只改了一部分的状态。
- 返回实际由未读变为已读的邮件数量；已经是已读的邮件不计入。

### R5 界面刷新与反馈

操作成功后 MUST 刷新左侧账号与文件夹未读数，并刷新当前邮件列表。

- 当前处于未读筛选时，已读邮件 MUST 从列表移出。
- 当前处于搜索状态时，MUST 用原关键词和筛选条件重新搜索，不得清空搜索框。
- 成功且数量大于 0 时，提示「已将 N 封邮件标为已读」。
- 成功且数量为 0 时，提示「没有未读邮件」。
- 失败时 MUST 显示可读原因，界面和本地数据保持操作前状态。

## 3. 接口设计

新增 Tauri 命令 `mark_all_read`。

请求字段：

- `accountId`：必填，正数。
- `folderId`：可选；为空表示账号全部文件夹，非空表示指定文件夹。

返回字段：

- `changed`：本次实际由未读变为已读的邮件数量。

校验规则：

- 账号编号必须是正数。
- 指定文件夹时，文件夹必须存在且属于该账号。
- 参数不合法时返回固定中文错误，不执行写入。

## 4. 数据更新规则

账号范围：

```sql
UPDATE message
SET is_read = 1, updated_at = <当前时间>
WHERE account_id = ? AND is_read = 0;
```

文件夹范围：

```sql
UPDATE message
SET is_read = 1, updated_at = <当前时间>
WHERE account_id = ? AND folder_id = ? AND is_read = 0;
```

更新完成后，在同一个事务内用 `message.is_read` 重算受影响文件夹的 `unread_count`，不依赖旧计数做加减，避免历史计数偏差被放大。

## 5. 边界情况

- 目标范围内没有未读邮件：返回 0，界面提示「没有未读邮件」。
- 操作进行中再次触发：按钮或菜单项应暂时不可用，避免重复执行。
- 账号或文件夹在操作前已被删除：返回可读错误，不执行写入。
- 批量操作不改变邮件的红旗、标签、附件或正文状态。
- 不提供批量撤销；需要恢复时仍按现有方式逐封标为未读。

## 6. 验收标准

1. 账号右键「全部标为已读」会先确认；取消后数据库无变化。
2. 确认后该账号所有文件夹的未读清零，其它账号完全不受影响。
3. 文件夹右键「全部标为已读」只清当前文件夹，同账号其它文件夹不受影响。
4. 没有未读邮件时返回 0，并显示对应提示。
5. 接口写入失败时邮件状态和文件夹未读数均保持原样。
6. 操作后账号未读数、文件夹未读数、统一入口未读数和邮件列表同步刷新。
7. 搜索状态下保持原关键词，重新搜索并反映最新已读状态。
8. 操作全程不发起网络请求，不生成服务器回写任务。

## 7. 不做范围

- 不做服务器批量 Seen 回写。
- 不做批量标为未读。
- 不做跨账号一键已读。
- 不做定时或自动清除未读。
