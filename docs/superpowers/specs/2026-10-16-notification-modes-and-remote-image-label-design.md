# 通知触发时机与远程图片文案调整设计

| 项目 | 内容 |
|---|---|
| 状态 | 待用户复核 |
| 日期 | 2026-10-16 |
| 范围 | 设置页通用分类中的远程图片文案、邮件系统通知开关与通知触发时机 |

## 1. 目标

- 把「默认拦截邮件里的远程图片」显示文字改为「拦截远程图片」。
- 把「新邮件用 Windows 系统通知提醒（窗口切到后台时才弹）」显示文字改为「启用邮件系统通知」。
- 增加通知触发时机三选一：不聚焦时通知、任何时刻都通知、仅在后台通知。
- 不改远程图片的实际拦截和单封放行行为，不改通知点击打开邮件等既有行为。

## 2. 行为定义

### 2.1 远程图片

- 原开关与后端字段 `blockRemoteImagesByDefault` 保持不变。
- 默认仍为拦截远程图片；关闭开关后仍按现有逻辑直接放行。
- 本次只改设置页显示文字，不改读信提示、放行按钮、记住发件人与后端规则。

### 2.2 通知总开关

- 原字段 `notifyNewMail` 保持不变，表示是否启用邮件系统通知。
- 关闭时前台、后台、任何时刻都不弹系统通知，只保留界面刷新。
- 开启时由通知触发时机决定什么时候弹。

### 2.3 通知触发时机

新增字段 `notifyNewMailWhen`，取值与含义如下：

| 取值 | 界面文字 | 含义 |
|---|---|---|
| `unfocused` | 不聚焦时通知 | 主窗口没有焦点时通知；窗口看得见但被别的窗口盖住也属于这一类 |
| `always` | 任何时刻都通知 | 无论主窗口有没有焦点、是否最小化或收进托盘，都通知 |
| `background` | 仅在后台通知 | 仅在主窗口最小化或收进托盘、窗口不可见时通知 |

- 默认值为 `unfocused`，保持现在「窗口不在前台就弹」的实际行为。
- 开关关闭时三选一仍然保留选中值，但界面置灰不可改；下次重新开启仍使用原值。
- 焦点或窗口可见状态读不出来时，按「宁可多弹、不要漏掉新邮件」处理：不因状态查询失败而拦截通知。

## 3. 界面

设置页「通用」分类中：

1. 远程图片开关文字改为「拦截远程图片」，保留勾选框。
2. 通知开关文字改为「启用邮件系统通知」，保留勾选框。
3. 通知开关下方增加一个下拉选项，标题为「通知时机」，选项为「不聚焦时通知」「任何时刻都通知」「仅在后台通知」。
4. 通知智能识别仍只跟随通知开关和三选一的最终判定；最终不弹系统通知时不调用识别，也绝不外发正文。

## 4. 存储与同步

- `settings.json` 增加 camelCase 字段 `notifyNewMailWhen`，旧配置缺字段时读为 `unfocused`。
- 该字段与 `notifyNewMail` 一样参与设置同步，键名为 `ui.notifyNewMailWhen`。
- 同步包缺少该字段时保持本机默认值 `unfocused`，不能覆盖成其它模式。

## 5. 验证

- 设置页显示文字与三选一选项正确，保存后刷新仍保持。
- 关闭通知开关后三种时机都不弹；重新开启后仍按原选中时机工作。
- `always` 在前台也弹；`unfocused` 在前台不弹、失焦弹；`background` 在可见但失焦时不弹、最小化或收进托盘时弹。
- 通知智能识别只在最终确定弹系统通知时执行。
- 旧配置、旧同步包和缺少新字段的测试数据都按 `unfocused` 兼容。

## 6. 不做的事

- 不改远程图片拦截、放行和记住发件人的功能规则。
- 不改通知正文内容、点击通知打开邮件、验证码按钮等既有行为。
- 不增加系统级勿扰模式或静音时间段。
