## 0. 现状与前置

能直接复用的东西：

- **系统保险箱**：`crates/mail-core/src/secrets.rs`，已有 `SecretStore` 接口、`KeyringSecretStore`、长凭据分片 `ChunkedSecretStore`、底层报错脱敏。新功能全部走它，不另写一套。
- **网络连接层**：`crates/mail-net`，`connect_tcp` 按「账号级 > 全局自定义 > 系统代理 > 直连」选路，`tls_wrap` 负责加密。GitHub 请求复用它，才能跟着用户的代理走（这点在国内网络下很实际）。
- **最小 HTTP 客户端先例**：`crates/mail-oauth/src/http.rs`，目前只支持表单 POST，做法可以照抄。
- **数据库**：`setting` 表是 key/value 结构，同步状态放这儿就够，不需要新迁移。
- **前端**：设置页已经是两栏结构（`src/SettingsWorkspace.tsx`），「账号与同步」分类里已经有邮件同步面板 `src/SyncPanel.tsx`（名字会撞，见 P-D7）。

工作区要新增的外部依赖（统一在根 `Cargo.toml` 的 workspace.dependencies 里声明）：

- `argon2`：口令派生。走 RustCrypto 的现成实现，不自造算法。
- `aes-gcm`：内容加密。同上。
- `zeroize`：内存里的明文用完擦掉。

## 1. 结构决策

- **P-D1 新建 `crates/mail-sync`**：加解密、GitHub 接口、Gist 读写、版本与冲突判定都放这儿。单独成 crate 是为了让最敏感的加解密部分能被单独测试、单独审阅。依赖方向 `mail-domain ← mail-sync`；`mail-sync` 不依赖 `mail-store`、不依赖 `mail-core`，保持底下一层，不制造环路。
- **P-D2 同步状态放 `setting` 表**：设备标识、Gist 编号、版本号、上次同步时间、上次错误各占一个键，统一 `sync.` 前缀。不新建迁移。
- **P-D3 密钥不经数据库**：导出时从保险箱读、进内存、加密出网；导入时解密、写回保险箱。数据库始终只有引用键，这条不松口。
- **P-D4 快照导出/导入放 `mail-core`**：只有它能同时摸到数据库和保险箱。`mail-sync` 只管「字节进、字节出」，不知道业务表长什么样，加解密逻辑就不会跟业务耦合。
- **P-D5 HTTP 客户端写在 `mail-sync` 里**：现有那份只支持表单 POST，Gist 需要 GET/POST/PATCH/DELETE 加 JSON 请求体和自定义请求头。新写一份通用的，但传输层仍然调 `mail-net`。
- **P-D6 待同步标记用去抖**：写操作成功后打标记，5 秒后合并成一次上传，后台任务做，不挡界面。
- **P-D7 界面命名必须分开**：现有 `SyncPanel` 是邮件收发同步，新面板叫「设置同步」，标题和图标都要能一眼分清。

## 2. Wave 划分与原子任务

### Wave S1：加解密底座

#### T1.1 建 crate 与错误类型
- **动作**：新建 `crates/mail-sync`，加进根 `Cargo.toml` 的 members 与 workspace.dependencies；定义统一错误类型。
- **文件**：`Cargo.toml`、`crates/mail-sync/Cargo.toml`、`crates/mail-sync/src/lib.rs`、`crates/mail-sync/src/error.rs`
- **出口**：`cargo check -p mail-sync` 退出码 0。
- **安全**：错误类型对外只给通用提示，不携带密钥、密码、明文。
- **回退**：删目录并从 members 移除。

#### T1.2 口令派生
- **动作**：实现 Argon2id 派生，参数（内存 64 MiB、迭代 3、并行 1、随机盐 16 字节）随包一起存，日后可升级。
- **文件**：`crates/mail-sync/src/crypto.rs`
- **出口**：同密码同盐派生出同一个键；不同盐结果不同。
- **安全**：派生键与密码用 `zeroize` 擦；不进日志。
- **回退**：删 `crypto.rs`。

#### T1.3 加解密
- **动作**：实现 AES-256-GCM 加密与解密，每次加密随机生成 12 字节随机数，绝不复用。
- **文件**：`crates/mail-sync/src/crypto.rs`
- **出口**：往返一致；错密码解不开；内容改一个字节也解不开。
- **安全**：解密失败不区分「密码错」和「内容被改」，统一报「解不开」，不给攻击者多余信息。
- **回退**：同上。

#### T1.4 出网包格式
- **动作**：定义出网包结构（格式名、格式版本、派生算法名与参数、盐、随机数、密文、设备标识、设备名、版本号、时间），实现序列化与解析，二进制字段走 base64。
- **文件**：`crates/mail-sync/src/envelope.rs`
- **出口**：序列化再解析回来一致；遇到不认识的格式版本给明确错误，不硬着头皮解。
- **安全**：这层只碰密文与公开头字段，不碰明文。
- **回退**：删文件。

### Wave S2：HTTP 与 GitHub 登录

#### T2.1 通用 HTTP 客户端
- **动作**：在 `mail-sync` 内实现最小 HTTP 客户端，支持 GET/POST/PATCH/DELETE、JSON 请求体、自定义请求头（授权头、接收类型、用户代理），传输复用 `mail-net`，自动走用户的代理设置。
- **文件**：`crates/mail-sync/src/http.rs`
- **出口**：用本机假服务器验证请求行、请求头、请求体拼装正确，状态码与正文能取回；覆盖 4xx / 5xx 分支。
- **安全**：授权头不进日志；错误信息先脱敏再返回。
- **回退**：删文件。

#### T2.2 设备码登录
- **动作**：向 GitHub 申请设备码与用户码，按返回的间隔轮询换令牌，处理「等用户确认」「慢一点」「已过期」「用户拒绝」四种结果。
- **文件**：`crates/mail-sync/src/github.rs`
- **出口**：假服务器覆盖上述四种结果，各有对应错误文案。
- **安全**：令牌只经内存回到上层，由上层写保险箱；日志只记状态不记令牌。
- **回退**：删文件。

#### T2.3 取用户资料
- **动作**：拿令牌取登录名、昵称、头像地址；缺字段时有兜底，不因一个空昵称就整段失败。
- **文件**：`crates/mail-sync/src/github.rs`
- **出口**：假服务器返回的字段正确解析；只返回部分字段时仍能成形。
- **安全**：请求头带令牌，令牌不进日志。
- **回退**：同上。

#### T2.4 令牌与资料落盘
- **动作**：`mail-core` 增加 GitHub 登录编排：登录成功后令牌写保险箱（键 `sync/github-token`），资料写 `setting` 表；登出时两处一起清。
- **文件**：`crates/mail-core/src/sync_settings.rs`（新）、`crates/mail-core/src/lib.rs`
- **出口**：用内存保险箱验证「登录后能取到、登出后取不到」；数据库文件字节里搜不到令牌。
- **安全**：头像地址可以入库，令牌不行。
- **回退**：删文件并去掉模块声明。

### Wave S3：Gist 客户端

#### T3.1 找出目标 Gist
- **动作**：列出当前账号的 Gist，按固定描述（`Y-Mail 设置同步`）和固定文件名（`ymail-sync.json`）挑出那一个；有多个时取最近更新的一个。
- **文件**：`crates/mail-sync/src/gist.rs`
- **出口**：假服务器返回多个 Gist 时能选对；一个都没有时返回「没找到」而不是报错。
- **安全**：只读元数据，不解密。
- **回退**：删文件。

#### T3.2 创建私密 Gist
- **动作**：建私密 Gist，描述和文件名固定，内容为出网包。
- **文件**：`crates/mail-sync/src/gist.rs`
- **出口**：假服务器断言请求体里 `public` 为假、文件名正确。
- **安全**：必须私密，代码里不允许出现建公开 Gist 的分支。
- **回退**：同上。

#### T3.3 读取 / T3.4 更新 / T3.5 删除
- **动作**：按 Gist 编号读内容、更新内容、删除。
- **文件**：`crates/mail-sync/src/gist.rs`
- **出口**：三条各有单测；覆盖 404（已删）、403（权限没了）、409（冲突）三类失败。
- **安全**：删除只由用户明确动作触发（关闭时勾选、或重设密码），不自动删。
- **回退**：同上。

### Wave S4：快照导出与导入

#### T4.1 快照结构
- **动作**：定义加密前的快照结构：版本号、设备信息、时间、界面开关、账号、代理、全局代理、签名、AI 站点、AI 功能映射、密钥字典。
- **文件**：`crates/mail-core/src/sync_settings.rs`
- **出口**：结构序列化往返一致。
- **安全**：结构里可以放密钥值，但只在内存里；这个结构绝不直接落库、绝不进日志。

#### T4.2 导出
- **动作**：从数据库读各类配置，从保险箱读对应的密钥，拼成快照。
- **文件**：`crates/mail-core/src/sync_settings.rs`
- **出口**：导出后断言密钥在快照里、数据库里没有密钥。
- **安全**：只导出 3.1 表格里列进来的字段；`dataDir` 这类本机专有字段明确不出现在结构里。
- **回退**：删函数。

#### T4.3 导入
- **动作**：按逻辑键匹配本机已有条目，命中就更新、没命中就新建；密钥写回保险箱。整段用事务，中途失败全部回滚。
- **文件**：`crates/mail-core/src/sync_settings.rs`
- **出口**：往返测试（导出 → 导入到空库 → 两边一致）；本机已有同邮箱账号时按规则更新；中途失败无半成品。
- **安全**：写入顺序是先保险箱后数据库，任一步失败要回滚另一侧。
- **回退**：删函数。

#### T4.4 逻辑键规则
- **动作**：账号按邮箱地址；代理按「标签 + 主机 + 端口」；AI 站点按标签；签名按名称。规则写成纯函数，单独测。
- **文件**：`crates/mail-core/src/sync_settings.rs`
- **出口**：规则表驱动测试，覆盖重名与改名两类情况。
- **安全**：逻辑键里不含密钥。
- **回退**：同上。

### Wave S5：同步编排

#### T5.1 状态键
- **动作**：定义 `setting` 表里的状态键：是否开启、设备标识、设备名、Gist 编号、当前版本号、上次见到的远端版本号、上次同步时间、上次错误。
- **文件**：`crates/mail-core/src/sync_settings.rs`
- **出口**：读写一致；缺键按默认值处理，老用户升级不受影响。
- **安全**：状态键里不存密码、不存令牌。
- **回退**：删函数。

#### T5.2 版本与冲突判定
- **动作**：上传时版本号加一；拉取前比对远端版本与本机记录的版本，远端更新且不是本机写的就判定为冲突。
- **文件**：`crates/mail-core/src/sync_settings.rs`
- **出口**：单测覆盖「没变化」「本机自己写的」「别的设备写的」三类；冲突时不自动导入。
- **安全**：判定只看元信息，不解密就能做。
- **回退**：删函数。

#### T5.3 待同步标记与去抖上传
- **动作**：账号、代理、签名、设置、AI 的写操作成功后打标记；后台任务等 5 秒，把期间多次改动合并成一次「导出 → 加密 → 上传」。
- **文件**：`crates/mail-core/src/sync_settings.rs`、`crates/mail-core/src/engine.rs`
- **出口**：连续改三次只产生一次上传（用假 Gist 计数）；上传失败记错误、不反复重试。
- **安全**：每次上传都重新生成随机数；不复用密文。
- **回退**：把标记调用去掉即可停用自动同步，不影响其它功能。

#### T5.4 启动拉取
- **动作**：主窗口就绪后拉起一次「拉取 → 解密 → 比对版本 → 无冲突就导入」。
- **文件**：`crates/mail-core/src/sync_settings.rs`、`src-tauri/src/lib.rs`
- **出口**：启动时远端有新版本能自动导入；有冲突不导入，只置状态。
- **安全**：解密失败不覆盖本机数据。
- **回退**：去掉启动调用。

#### T5.5 四个动作
- **动作**：开启（设密码、建 Gist）、关闭（可选删远端）、重设密码（建新 Gist 删旧 Gist）、新设备加入（找 Gist、输密码、导入）。
- **文件**：`crates/mail-core/src/sync_settings.rs`
- **出口**：四个动作各有单测，用假 Gist 与内存保险箱；重设密码后旧密码解不开。
- **安全**：旧 Gist 删除失败要返回明确提示，让用户知道可能还有残留。
- **回退**：逐个动作可单独去掉。

### Wave S6：外壳命令与界面

#### T6.1 外壳命令
- **动作**：新增独立文件承载命令，避免把已经很大的 `commands.rs` 撑得更大：登录开始 / 登录轮询 / 退出登录 / 取资料 / 查询同步状态 / 开启同步 / 关闭同步 / 立即同步 / 重设密码 / 新设备加入 / 解决冲突。
- **文件**：`src-tauri/src/sync_commands.rs`（新）、`src-tauri/src/lib.rs`、`src-tauri/src/state.rs`
- **出口**：命令能注册进 Tauri 并编译通过；参数校验（比如密码长度）返回可读错误。
- **安全**：命令入参里的密码不落日志；错误信息不带明文。
- **回退**：删新文件与注册项。

#### T6.2 前端接口封装
- **动作**：`api.ts` 增加各命令的类型与调用。
- **文件**：`src/api.ts`
- **出口**：类型检查通过（`npm run build`）。
- **安全**：前端不持久化密码与令牌，只在内存里待到提交。
- **回退**：删新增部分。

#### T6.3 GitHub 登录面板
- **动作**：显示用户码、复制按钮、重新打开浏览器链接、轮询状态；登录后显示头像与昵称，提供退出登录。
- **文件**：`src/GitHubLoginPanel.tsx`（新）
- **出口**：前端测试覆盖「显示用户码 → 轮询成功 → 显示头像」。
- **安全**：头像只从固定域名加载；不把令牌放前端状态里。
- **回退**：删文件。

#### T6.4 设置同步面板
- **动作**：开关、密码设置（两次输入）、同步状态、立即同步按钮、Gist 链接、错误提示、冲突选择框；开启前必须让用户勾选「我明白私密 Gist 并非真正私有」和「AI 密钥会一起同步」两条说明。
- **文件**：`src/SettingsSyncPanel.tsx`（新）
- **出口**：前端测试覆盖密码不一致、未勾选、开启成功三条路径。
- **安全**：密码输入框用密码类型；不写入本地存储。
- **回退**：删文件。

#### T6.5 接进设置页
- **动作**：在「账号与同步」分类里把新面板放在邮件同步面板下方，标题写「设置同步」，与「同步状态」明确区分。
- **文件**：`src/SettingsWorkspace.tsx`
- **出口**：目视与测试都能确认两个面板并存且标题不同。

#### T6.6 词条与样式
- **动作**：中英词条补齐；新面板样式沿用现有卡片与按钮风格，配色走主题变量。
- **文件**：`src/i18n.en.ts`、`src/index.css`
- **出口**：切换英文界面时新文案不缺词条。
- **安全**：不涉及。
- **回退**：删新增规则。

### Wave S7：加固与验收

- **T7.1 后端测试补全**：加解密往返与篡改、冲突判定、逻辑键匹配、导入回滚、去抖合并。文件：各模块的测试段；出口：`cargo test -p mail-sync -p mail-core` 全绿。
- **T7.2 前端测试**：新增 `src/__tests__/settingsSync.test.tsx`；出口：`npm test` 全绿。
- **T7.3 真机走查**：`npm run tauri dev`，用两个账号或两台机器走「开启 → 改配置 → 拉取 → 制造冲突 → 重设密码」。出口：每一步都能看到预期结果；这块必须人工，自动化替代不了。
- **T7.4 安全复查**：直接打开 Gist 原文，确认只有密文；用文本工具在数据库文件里搜授权码、代理密码、AI 密钥、GitHub 令牌，确认搜不到；检查日志文件同样搜不到。出口：三项都搜不到。
- **T7.5 五关**：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`、`npm run build`、`npm test`。出口：退出码全 0，日志存 `.ai-memory/20261008/gist-sync/`。
- **T7.6 更新记忆**：`.ai-memory` 的 handoff、project_memory、当日 daily。

## 3. 测试策略

- **优先测纯逻辑**：加解密、版本判定、逻辑键匹配都是纯函数，用单元测试覆盖到位，不依赖网络。
- **网络一律用假服务器**：设备码、取资料、Gist 读写全部注入假服务端，CI 不碰真 GitHub。真 GitHub 只在 T7.3 人工走一遍。
- **保险箱用内存实现**：沿用现有 `MemorySecretStore`，CI 不依赖真实系统凭据库。
- **必测的安全断言**：数据库文件字节里搜不到密钥明文；导出快照里密钥在、数据库里不在；错密码不覆盖本机数据。
- **前端测试**：密码校验、勾选确认、状态展示、冲突弹窗。

## 4. 风险与回退

| 风险 | 影响 | 应对 |
|---|---|---|
| Argon2id 参数在低配机器上太慢 | 每次同步都卡一下 | T1.2 实测；超过 1 秒就往下调内存，参数随包存所以能升级 |
| 同步包超过单文件读取上限（约 1 MB） | 拉不回来 | T4.2 实测包大小；超了就拆成多个文件 |
| 国内访问 GitHub 不稳 | 同步失败 | 请求走用户代理设置；失败给可读提示，不反复重试 |
| 私密 Gist 历史版本累积 | 旧密文留在历史里 | 界面说明这一点；重设密码时建新 Gist 而不是改旧的 |
| 冲突弹窗太频繁 | 打扰用户 | 只在真冲突时弹；上传前先拉取比对，避免误判 |
| 头像远程加载被拦 | 头像不显示 | 这是全程序唯一放行的远程图片，来自固定域名；同时本机缓存一份 |

回退总原则：本功能整体可关。关掉同步后，后端不再上传，前端不再显示状态；已同步的数据留在本机不回滚（因为那是用户自己的配置）。
